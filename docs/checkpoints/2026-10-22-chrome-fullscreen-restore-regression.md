# Chrome 跨屏后未恢复全屏的回归

- 用户确认：安装版20261022092807中的Chrome原本已全屏，Cmd+方向键移屏后变成普通窗口。此前空白窗口双向验收通过，不能覆盖这次间歇失败；Chrome全屏恢复重新列为未完成实机验收。
- 当前事实：原菜单路径只尝试一次，焦点或菜单暂不可用时直接进入失败恢复；Release编译未启用全屏阶段记录。本次50秒只读采样未捕获跨屏，不能用后续AXFullScreen=true的快照解释历史失败。
- 候选修正：Chrome在精确目标窗口保持前台时，最多等待4秒菜单就绪；焦点改变、目标退出、操作代次/恢复意图改变时停止，不激活其他窗口。等待期间重新读取全屏状态，已达到目标则不发送toggle。命令至多发送一次；AX发送结果不确定也先观察实际状态，不从其他控制路径重试。
- 保留：禁止Chrome的AXFullScreen写入和绿色窗口按钮回退；精确窗口身份、阶段位置检查、最终4秒稳定验证和失败恢复保持。尚未证明这就是用户这次失败的根因。
- 诊断：仅本机WE1Debug身份的Release包开放fullScreenDisplayMove和chromeFullScreenRequest两个现有记录流；仅数字、布尔和固定状态码，沿用限频、1MiB轮换、0600和后台写入，不保存标题、URL或正文。正式生产身份仍不记录。
- 验证：47项针对性XCTest通过，包含新的等待、焦点改变、代次失效、未知发送结果不重试、超时和Release诊断准入检查；日志见build/ChromeFullScreenRegression/tests-final.log。
- 合并范围：当前分支fix/chrome-fullscreen-restore-20261022基于设置窗口修复6c7826f，新候选包含两个修复；keep-awake未改，未推送、未合并、未安装。原生复测待备份安装授权后进行。
