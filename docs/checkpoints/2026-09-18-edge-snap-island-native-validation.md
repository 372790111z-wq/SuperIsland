## 本轮发现与证据限制

1. 多次有效分屏拖动过程中，主灵动岛面板也从 168×32 扩为 762×257，松手后短暂保留。主岛悬停入口没有与 `WindowDragInteractionMonitor` 的实际拖窗状态互斥。这是需要继续处理的交互问题，本轮未修复。
2. 首次右上四分之一区域尝试没有形成有效拖窗：测试窗口几何完全未变、分屏岛未出现。主岛大面板覆盖了该起点的几何范围，但其中含透明区域，因此不能断言它截获了那次点击。移开鼠标、等待收起后重新测试，该区域通过。
3. 工具最初只检查普通 layer 0 窗口；直接扩大到所有 CG 面板又会把 Dock 等透明全屏面板当成遮挡。最终在每次准备阶段移开鼠标，结合普通窗口前后顺序和 AX 命中应用校验起点；命中其他应用时停止，不发送按下。
4. 最初取消用例的零停留不等于在展开前松手，因为移动路径本身可能已停留超过触发延时。最终提前取消改为从触发区外快速进入，以松手前的实际标记形态为证据；空隙/移出用例增加停留，核对展开、取消和释放后的状态。早期受遮挡/时序影响的尝试不计入通过结果。
5. 部分拖动中的布局预览采样仍处于动画或异步更新期间，边界与最终落位不同。本轮未逐帧核验预览的稳态位置和延迟，因此只确认最终落位，不宣称整个拖动过程中预览视觉完全一致。
