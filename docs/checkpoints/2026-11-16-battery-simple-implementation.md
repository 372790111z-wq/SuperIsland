## 实现

1. 岛内与设置页共用 `BatterySimpleProtectionView`：保护开关、80–100% 上限草稿与明确提交、主动放电目标/停止、必要状态与恢复入口。删除旧分区、趋势及高级控制 UI；右键仅打开设置。
2. `BatterySimplePreferences` 使用新的配置键，旧偏好只备份一次。有效旧上限可迁移；低于 80%、损坏或未知的旧上限需要用户明确重新选择。旧版没有持久启用意图，迁移不会猜测为开启。
3. 关闭意图独立于恢复责任持久保存。重启先读取全局控制是否仍被持有；未知不当作已经解除，旧 helper 不兼容时不获得新控制权。失败不由心跳偷偷重试新写入。
4. 应用服务和辅助程序双层拒绝旧高级请求；helper 协议升为 19，要求新请求标识。旧定时器不启动、手动运行旧任务被拒绝；旧写入 AppIntents 不再可发现，已存捷径也返回功能已移除。只读上限查询优先读取新配置，不产生迁移或控制写入。
5. 保留自有变更比较恢复、持久日志、冲突拒绝、断供恢复及正常失联看门狗。旧退出保持不能新建，历史记录仍能恢复；不新增保持唤醒、锁屏或屏幕控制。
6. 辅助程序直接监听系统电源事件。睡眠中断主动放电，记录被中断的操作身份（包括睡眠后才到达的旧请求），唤醒后拒绝旧操作续跑。只保留已有控制租约，唤醒后回到 45 秒失联窗口；客户端不能通过伪造 sleeping 来无限续租。
7. Native/BCLM 通道保留硬件限值；仅靠软件电量采样的 SMC 通道在睡眠期间暂停充电以避免越过上限，100% 选择不额外暂停。没有阻止睡眠或创建唤醒计划。以上为实现策略，尚不是本机睡眠效果验收。
8. 不把接口接受当作实际放电：只有有效负电流才显示“正在主动放电”；未知供电/充电分别显示未知，不推成未接电或未充电。

## 对抗性审查

| 反例 | 处理与证据 |
| --- | --- |
| 隐藏 UI 后旧定时/捷径仍写硬件 | 调度与手动入口停止；应用与 helper 同时拒绝旧模式/高级偏好；注入测试证明闭包不执行 |
| 关闭失败后重启自动开启 | 关闭意图与恢复义务分开保存，重启只观察恢复，显式重试不擅自开启 |
| 应用上限失败却保存了新值 | 保留旧有效值和新草稿，释放自有控制并显示未生效；失败注入通过 |
| 旧 helper 或他人控制被当成空闲 | 必须匹配协议且全局控制明确为空；未知/被占用均不提交 renew |
| 晚到 renew 覆盖手动关闭 | revision fence 与持久关闭意图；回调竞态测试通过 |
| 睡眠前/睡眠中排队的放电在醒来恢复 | 内核睡眠边沿记录操作身份，旧操作归一为自动模式；两个时序用例通过 |
| 睡眠事件使已过期租约复活 | 入睡前先检查到期；已过期执行恢复，不续租 |
| 退出后无限保持控制 | 禁止新退出保持，普通退出释放；醒来后恢复有限看门狗；旧持久记录保留恢复 |
| 查询与 UI 不同上限 | 只读查询优先新配置，测试确认不改写配置或启动迁移 |
| 放电后读数消失导致停止按钮失效 | 停止按恢复动作处理，不依赖当前电量或适配器读数；最终安全用例覆盖 |
| 请求接受就显示硬件成功 | 实际负电流和供电/充电有效性控制状态文案；未知不补为否 |
| 迁移覆盖旧数据或借精简放宽能力门槛 | 单次备份，旧任务存储原样保留；未改放电能力/恢复验证 gate |

审查未发现需在本轮代码交付前阻断的新控制入口漏洞；设备验收仍是独立门槛。
