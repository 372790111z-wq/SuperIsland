## 证据与未知

- 旧 105549 的 normal quit 记录只有 API `accepted=true`，SIGTERM 只有发送成功。进程采样是普通 AppKit run loop，没有退出决定或恢复原因日志。不能据此认定旧现场已进入 `applicationShouldTerminate`，更不能确认是哪项保护取消了退出。
- 源码能证明两条持续拒绝路径：已结束事务保留 `.unresolved`，而再次退出只向活动任务请求恢复；匿名收起窗口旧 AX 对象失效后，即使成功快照不再包含它，也始终归入暂时不可识别并保留。
- 这两条是静态缺陷证据，并非旧现场根因的实测。直接清旧结果或整个批次会丢失尚未履行的恢复责任；本轮只补诊断，不放宽退出或恢复条件，不把后续其他窗口成功当作旧窗口恢复。

## 实现

- 独立 `termination.jsonl`，复用已有有界生命周期写入器，最多两个 256 KiB 文件、0600 权限、128 项有界队列、序号及丢弃范围；不受鼠标日志节流。仅 DEBUG 的 WE1 bundle 可落盘。
- AppDelegate 记录启动、信号、退出请求进入、已有请求处理中、立即允许、延迟任务起止和最终退出；每次请求带编号，重复请求指向活动编号，最终退出指向真正获准的编号。来源只区分 AppKit 与 SIGTERM，不猜测菜单或外部调用来源。
- 控制器记录事务类型、代次、完成枚举，以及退出阶段中的活动任务、恢复意图和收起批次计数。准备结束保留允许结果、批次结果及耗时；恢复过程中只在内存快照或原因计数变化时记录。
- 收起控制器仅统计原有检查分支：应用退出、快照失败、身份冲突、匿名目标不可识别、缺失待确认/退役、最小化状态不可读、恢复不可写/写失败/等待回读/已恢复。读取诊断快照不调用任何环境闭包，不新增 AX 查询。
- 最终退出前最多等待专用写入器 150 ms，超时不阻止退出，不增加 terminateLater 握手。慢盘或异常退出可能丢失尾部记录，因此缺少日志不能单独证明某个阶段未发生。
- 不记录目标应用名、窗口标题、路径、文件内容或截图。退出保护、18 秒期限、恢复短路顺序、窗口所有权和激活行为保持原样；当前两个静态缺陷尚未修复。
