## 目标与范围

用户调节音量或 Mac 内置屏幕亮度时，能在灵动岛中看到图标、进度条和百分比，提示结束后恢复原内容。macOS 出现可读取的新通知横幅时，用户能在岛内获得提醒并查看最近通知。

| 工作项 | 实施前源码事实 | 本次目标 |
| --- | --- | --- |
| 音量提示 | 已有音量管理、键盘事件处理、收起态提示和展开控件 | 复用现有能力，明确临时显示、恢复及并发规则 |
| 屏幕亮度 | 尚未发现内置屏幕亮度展示实现；现有亮度管理仅处理键盘背光 | 新增 Mac 内置屏幕亮度反馈 |
| Mac 通知来源 | 已有扩展、WhatsApp 和兼容广播来源；辅助功能横幅读取仅用于部分 WhatsApp 处理 | 增加系统可见通知横幅的接入，能力覆盖通过原生实测确认 |
| 通知展示 | 已有短时提醒、列表、预览偏好和来源管理 | 复用现有通知模块，接入新来源并处理正文隐藏、去重和并发 |

本期不包含外接显示器亮度控制、键盘背光提示、独立亮度控制面板、聊天回复、系统通知删除、通知私有数据库读取、完整历史补录或云端转发。HTML 右侧的滑杆、场景选择器和“模拟新通知”按钮仅是演示工具，不进入业务界面。

## 已确认行为与技术边界

1. 音量、亮度在调节时短暂显示图标、进度条和百分比，随后恢复；亮度首版支持 Mac 内置屏幕。
2. 根据显示器是否有实体刘海选择形态：有刘海时，调节提示临时向两侧拓宽，左侧图标、右侧进度条和百分比，结束后恢复原尺寸；没有刘海时，使用完整胶囊，保持原尺寸。此修正已由用户在 2026-10-14 实机测试后明确确认。HTML 中的 `220 × 36` 是模拟尺寸，不覆盖不同硬件和用户外观设置。
3. 调节提示在最后一次调节后 1.5 秒结束；通知自动提醒在无用户交互时展示约 2 秒。连续调节重新计时。
4. 调节反馈优先于自动通知提醒。并发通知先进入列表，调节结束后展示最新待提醒项，不因暂未展示而丢失其余列表记录。
5. 保留系统原生通知横幅；岛内正文预览可单独关闭。系统没有提供的发送者、标题或正文不通过其他渠道补取。
6. 通知接入目标是“Mac 通知联通”，首期验收对象是系统可见且可解析的新通知横幅。全部 App 的覆盖、静默通知、锁屏通知和完整历史通知读取均未获技术验证。

Apple 的 [`getDeliveredNotifications(completionHandler:)`](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/getdeliverednotifications(completionhandler:)) 返回本应用已送达的通知，不能作为读取其他 App 通知的通用接口。当前项目中的通知 UI 辅助功能读取可作为技术候选；它能否稳定覆盖本机系统和目标 App，须在实现阶段验证。

## 功能点 1：音量短时提示

### 1. 业务目的

用户调节系统音量时能快速确认当前值和静音状态，提示结束后继续查看原来的岛内内容。

### 2. 使用者

已开启音量提示的本机用户。音量不可由系统调节的输出设备不应显示虚构数值或成功反馈。

### 3. 触发

用户通过音量键、静音键、控制中心音量滑块的鼠标拖动或应用内音量控件进行操作，并获得当前输出设备的有效状态。不因初始化、设备枚举或媒体 App 刷新而弹出提示；控制中心入口必须确认用户正在操作对应滑块，不把后台变化当作调节事件。

关键原生节点：音量模块开关 `system-feedback-volume-toggle`、音量短时提示 `system-feedback-volume-hud`。已写入源码；开关 ID 已在本机原生运行树定位。

### 4. 流程

1. 接收用户调节事件，更新实际音量及静音状态。
2. 收起状态下显示音量图标、进度条和百分比；实体刘海屏在两侧显示，无刘海屏在完整胶囊显示。
3. 静音时显示静音图标和有效静音状态；解除静音后按真实读值恢复。
4. 连续调节更新同一提示，并从最后一次操作重新计时。
5. 1.5 秒后恢复原内容；如有待提醒通知，按功能点 5 处理。

### 5. 规则

- 沿用现有音量键步进、细调和静音行为，不根据演示按钮的步长改写真实系统规则。
- 进度条与数值取自当前设备状态，范围为 0–100%，不能越界。
- 收起态显示不新建第二个悬浮提示窗口，不自动展开控制面板。
- 现有展开音量控件继续沿用原流程；本次不重做媒体 App 音量控制。
- 关闭音量提示后停止岛内反馈，但不阻止用户继续调节系统音量；原生按键处理必须保持可用。

### 6. 边界

- 上下限：到达 0% 或 100% 后继续操作，不产生越界值。
- 输出设备变化：重新读取当前设备，旧设备的读值不能覆盖新设备。
- 设备不支持或读取失败：不伪造百分比，不吞掉应由系统处理的按键。
- 辅助功能不足：沿用现有权限状态及降级处理，不在后台重复弹权限请求。
- 应用初始化和后台音量查询不应触发用户调节提示。

### 7. 数据

复用 `VolumeManager` 的音量、静音和输出设备状态，以及现有 `volumeHUDEnabled` 偏好。提示计时和被临时覆盖的呈现状态为运行时数据，不持久化，不新增远程接口。

### 8. 验收

- [ ] 实际调节音量和静音时，图标、数值及进度条与当前设备一致。
- [ ] 实体刘海屏在提示期间侧向拓宽，结束后恢复原尺寸；无刘海屏保持原尺寸，恢复原内容后可继续使用。
- [ ] 连续调节不会在最后一次操作后 1.5 秒之前提前恢复。
- [ ] 0% / 100%、静音切换及输出设备变化不会显示旧值或越界值。
- [ ] 关闭提示、权限不足或不支持的输出设备均不会使系统音量键失效。

## 功能点 2：Mac 内置屏幕亮度短时提示

### 1. 业务目的

用户调节内置屏幕亮度时获得与音量一致的反馈，能分辨调节对象和当前亮度。

### 2. 使用者

具有可读取亮度的 Mac 内置屏幕、且开启亮度提示的本机用户。仅连接外接显示器的设备不属于首版硬件范围。

### 3. 触发

用户通过亮度键或控制中心显示器亮度滑块的鼠标拖动，调节受支持的内置屏幕亮度，并取得有效亮度值。不把键盘背光事件当成屏幕亮度事件；控制中心入口须确认对应滑块上的用户手势。

关键原生节点计划：亮度模块开关 `system-feedback-brightness-toggle`、亮度提示 `system-feedback-brightness-hud`。

### 4. 流程

1. 识别内置屏幕及其能力，读取有效亮度。
2. 用户调节后显示太阳图标、进度条和百分比。
3. 收起态按实体刘海/无刘海形态显示，连续调节更新同一提示；实体刘海屏可临时侧向拓宽。
4. 最后一次调节后 1.5 秒恢复原内容。
5. 硬件不支持或读取失败时保留原内容，并在设置的能力状态中说明原因。

### 5. 规则

- 百分比由实际读值换算，不能使用固定默认值模拟接通。
- 不增加控制系统亮度的业务滑杆；HTML 滑杆仅用于演示显示行为。
- 不接管外接显示器亮度，不调整键盘背光。
- 关闭提示后不影响系统亮度调节。
- 用户正在操作已展开界面时，不因亮度变化强制收起或切走其模块；本期新增的自动短时提示以收起态为主流程。

### 6. 边界

- 内置屏幕不存在、不支持读取或当前不可用时，不显示“已接通”。
- 读值不合法、接口失败或显示器状态变化时，不复用过期百分比。
- 系统实际最小亮度不等于关闭屏幕，不根据显示 0% 触发关屏。
- 初始化、自动亮度变化等非用户调节事件不得制造重复提醒；具体事件区分能力需记录实测结果。
- 亮度技术路线仍待实现验证，HTML 模拟成功不能作为硬件验收。

### 7. 数据

所需语义状态：内置屏幕标识、亮度读值、能力/错误状态及短时提示计时。新增亮度提示偏好与现有音量提示偏好独立；具体字段名和系统接口在实施时确定，不能引用键盘背光状态充当来源。

### 8. 验收

- [ ] 在目标 Mac 内置屏幕上，真实调节后图标、百分比和进度条与读值一致。
- [ ] 连续调节与自动恢复行为和音量提示一致；实体刘海屏临时侧向拓宽后恢复，无刘海屏尺寸保持不变。
- [ ] 仅外接显示器、能力不支持和读取失败均无虚构数值或成功状态。
- [ ] 提示关闭后仍可通过系统原有方式调节亮度。
- [ ] 不修改键盘背光或外接屏幕状态，不打断正在使用的展开界面。

## 功能点 3：Mac 系统通知来源与权限状态

### 1. 业务目的

将系统已向用户展示的新通知接入灵动岛，降低用户来回查看系统横幅的成本，并如实说明来源能力。

### 2. 使用者

主动启用 Mac 通知同步并允许所需辅助功能访问的本机用户。未启用、权限不足、不可读取或锁屏时不宣称已经联通。

### 3. 触发

入口为现有“设置 → 模块 → 通知”中的 Mac 通知来源及接入状态。用户启用后检查能力；收到可读取的新系统横幅后才产生通知记录。

关键原生节点计划：Mac 通知来源开关 `system-feedback-mac-notifications-toggle`、接入状态/权限入口 `system-feedback-mac-notifications-status`。

### 4. 流程

1. 用户在通知模块中启用 Mac 通知来源。
2. 检查当前权限及系统通知 UI 可访问性；未允许时说明原因，并提供明确的系统设置入口。
3. 条件满足时进入“等待系统通知”状态，不把“尚无消息”当作失败，也不在未验证来源时显示全面接通。
4. 从可读取的系统横幅提取 App、可见标题/发送者、可见正文及标识信息。
5. 验证来源和字段后交给现有通知模块，执行去重、列表保存与提醒。
6. 禁用来源或能力失效时停止新增采集，更新状态；恢复后只处理新事件，不自动补扫私人历史。

### 5. 规则

- 使用独立来源语义，不能把系统横幅全部归为 WhatsApp 或扩展。
- 权限状态与实际接入状态分别呈现；系统通知授权不等同于读取其他 App 通知的权限。
- 首次未配置状态应先说明访问范围，由用户主动启用/允许；不通过文档确认自动更改系统权限。
- 只处理可见、可识别的新通知横幅。不访问通知私有数据库，不上传消息，不读取 App 聊天记录补取内容。
- 系统隐藏或未暴露的字段保留为空。来源不确定时不能把某 App 的消息归给另一个 App。用户于 2026-10-14 明确确认：系统不暴露来源时，可将可见的新横幅以“Mac 通知”接入，App 标识为空、无点击跳转，正文仍默认隐藏。
- 保留原生系统横幅及系统通知设置，不主动关闭 App 原有通知。

### 6. 边界

- 辅助功能拒绝、撤销或通知 UI 不可访问：停止采集，状态可见，不重复自动请求权限。
- 锁屏：暂停岛内通知展示，不尝试读取或补取锁屏隐藏内容。
- 勿扰、静默投递或无可见横幅：没有可读取事件时不生成记录；不声称已覆盖这些消息。
- 系统版本、App 通知样式和语言差异：按实际可解析性降级，不能把部分成功写成全 App 支持。
- 启用、解锁或读取权限/界面恢复后的约 2 秒用于建立既有横幅基线，避免旧持续横幅重播；这一窗口内的新通知也可能被视作基线而不提醒，不能声称覆盖。
- 网络断开不影响本地已经显示的横幅读取；源 App 是否能收到网络消息由该 App 决定。

### 7. 数据

所需语义：来源类型、来源事件标识、App 名称/可核验标识、标题、可见发送者/正文、显示时间、接入状态和错误原因。优先复用 `IslandNotification` 与现有来源管理；新增字段仅用于缺失语义，不建立第二套通知列表。

权限及采集状态应能区分未启用、缺权限、等待横幅、已读取事件和能力不可用。不持久化通知正文到新日志或调试文件；验收记录仅保留版本、来源、结果和脱敏证据。

### 8. 验收

- [ ] 在目标 macOS 上，使用测试内容产生真实系统横幅，岛内出现对应的新通知记录。
- [ ] 实测记录列明系统版本、来源 App、样式与成功/失败，不笼统声称全系统接通。
- [ ] 未启用、缺权限、锁屏或横幅无法读取时，无虚构通知或成功状态。
- [ ] 权限撤销和来源禁用后停止新增采集，原生通知继续工作。
- [ ] 没有读取私有通知数据库、聊天历史或向远端发送消息内容。

## 功能点 4：通知提醒、正文预览与最近通知

### 1. 业务目的

用户在岛内快速识别新消息，并能查看最近记录；同时遵从系统正文隐藏和用户预览偏好。

### 2. 使用者

收到受支持来源通知的用户。Mac 通知接入失败时，已有扩展及其他来源仍应按原流程工作。

### 3. 触发

通过验证的新通知进入现有通知模块。关键节点计划：短时通知提示 `system-feedback-notification-banner`、正文预览开关 `system-feedback-notification-preview`、最近通知列表 `system-feedback-notification-list`、清除入口 `system-feedback-notification-clear`。

### 4. 流程

1. 自动提醒呈现 App 图标/名称、可用发送者或标题，必要时显示“新通知”。
2. 允许预览且系统提供正文时显示正文；否则不暴露正文。
3. 无用户交互时约 2 秒后恢复；用户按现有入口展开通知模块时停止该自动收起。
4. 查看最近通知，支持移除单条或清空岛内列表。
5. 来源可可靠识别时，通知动作可打开来源 App；没有可靠目标时不显示虚假的可跳转状态。

### 5. 规则

- 新增 Mac 通知来源默认隐藏正文，可在同一通知模块内明确开启；保留已有通知来源的预览偏好，不静默重置现有设置。
- 现有全局隐藏预览规则仍优先；Mac 来源的设置不能绕过全局关闭或系统隐藏状态。对应控件须解释禁用原因，避免两个开关相互矛盾。
- 仅对可确定为同一事件的重复采集做去重。两条内容相同的新消息不能仅因正文一致而被合并。系统卡片被遮挡或短暂不可读后重新出现，不重放同一卡片；身份仅在本次启用期间留存且有上限。系统复用同一 AX 卡片且内容也完全相同的连续通知无法可靠区分，应列为覆盖限制。
- 不以解析刷新或重复通知延长/重放已结束的提醒。
- 列表复用现有保留数量：默认 10 条，遵从用户已保存的值及现有 1–50 条边界。达到上限移除最旧项。
- 移除和清空只操作岛内列表，不删除、已读或回复来源 App 消息，也不清除 macOS 通知。
- 沿用现有通知展开布局及外观设置，不照搬 HTML 演示列表的固定尺寸。
- 打开 App 不等于打开指定聊天会话；精准会话跳转不纳入首版承诺。

### 6. 边界

- 空列表显示“没有通知”，保留来源设置入口。
- 缺失图标、发送者或标题时使用可核验来源及通用占位，不编造联系人。
- 长标题/正文按现有布局截断，不溢出或遮挡操作。
- 系统隐藏正文时，即使开启预览也只能显示隐藏提示或通用新通知提示。
- 用户已移除的同一事件不能被轮询立即重新插入；新的独立事件仍正常入列。
- App 已卸载、来源无法识别或打开失败时给出明确反馈，不声称已跳转。

### 7. 数据

复用现有最近通知数组、最新通知、保留数量及去重/移除记录。为 Mac 来源补充所需正文预览偏好；具体存储键在实施时确定，不改变旧键的既有含义。

## 功能点 5：提示优先级与恢复

### 1. 业务目的

避免音量、亮度与通知争抢岛内空间，使用户能看见当前调节反馈，同时保留并发消息。

### 2. 使用者

同时使用系统调节提示和通知模块的用户。正在操作展开界面的用户不应被后台通知强制打断。

### 3. 触发

调节反馈尚未结束时收到通知、短时间连续切换音量/亮度，或用户手动打开/关闭通知模块。

此功能点是呈现规则，复用前述提示及列表节点，不增加业务入口或演示按钮。

### 4. 流程

1. 调节事件覆盖当前自动提示，音量与亮度按最后一次有效操作显示。
2. 期间收到的新通知立即进入最近列表，将最新项标为待提醒。
3. 调节计时结束后，有待提醒项则展示通知，否则恢复被临时覆盖的原内容。
4. 用户主动进入列表后，新增消息更新列表，不自动关闭用户正在操作的界面。
5. 用户关闭对应模块、清除待提醒记录或退出应用时，取消对应待执行提示及计时。

### 5. 规则

- 收起态自动提示优先级：最新用户调节反馈，高于自动通知提醒，高于原有被动内容。
- 多条并发通知全部按保留规则入列；自动提示可只展示最新项，不逐条长时间占用岛。
- 原内容按现有模块的实际状态恢复，不能硬编码为演示中的“正在播放”或 82% 电量。
- 不把旧计时器的回调用于关闭更新后的提示；连续事件应取消或替换旧计时。
- 用户正在操作的展开/全展开界面及已有拖放、呈现保持、交互抑制规则优先；不因后台事件强制切换模块。
- 关闭通知来源后不再显示它的待提醒项；清除单条后不能再从待提醒队列重现。

### 6. 边界

- 音量与亮度交替变化：只显示最后一次有效调节，旧回调不抢占新提示。
- 同一通知已在提醒中又发生调节：记录仍保留，恢复时不插入重复列表项。
- 列表正在打开时通知到达：更新列表，保持用户操作状态。
- 模块禁用、来源失效和应用退出：取消相关定时及监听，不出现残留提示。
- 系统原生横幅不因岛内的排队或清除操作而被删除。

### 7. 数据

所需运行时语义：当前临时提示类型、最近调节时间、有效计时标识、恢复目标及待提醒通知标识。待提醒只引用现有列表中的事件，不复制消息内容建立另一份真源。临时呈现状态不持久化。

### 8. 验收

- [ ] 调节时收到的通知进入列表，并在调节提示结束后展示最新待提醒项。
- [ ] 多条并发消息在保留数量内都可查看，没有因自动提示覆盖而丢失。
- [ ] 音量/亮度交替操作不会被过期计时器提前关闭。
- [ ] 用户进入列表或使用展开界面时不会被后台通知强制收起或切走。
- [ ] 关闭模块或移除待提醒记录后，不再出现已取消的提示。
- [ ] 自动提示结束后恢复真实的原模块内容，无演示数值残留。
