## 2. 目标与范围

把 AlDente 的电池管理能力整合进 SuperIsland 现有电池模块，让用户在灵动岛查看仪表读数、调整充电和查看趋势，在 SuperIsland 设置窗口管理长期规则和自动化。

本需求包含完整功能目标：充电限制与低于 80% 开关、自动/手动放电、临时充满、暂停充电、航海模式、过热保护、五阶段校准、仪表指标、睡眠行为、能源模式、定时任务、12 项捷径、显示偏好、硬件电量指标、Intel 分支及 MagSafe LED。不能因某项技术尚未验证而默默移出范围或保留一个无效果按钮。

依赖设备、系统或权限的能力允许明确显示“不支持 / 未授权 / 待恢复”；只有实际执行、回读及相应设备验收通过，才可以作为已支持能力交付。未支持能力应登记原因和待完成工作，不能以原型模拟顶替。第6.1节列出PRD核对后发现的原型差异，未补稿并确认前不将其称为已经通过HTML验收。

## 4. 通用状态、数据与执行原则

### 4.1 状态分层

1. **设备读数**：百分比、接电、正在充电、温度、容量、电压、电流、时间、数据来源与采样时间。缺失为“— / 暂不可用”，不填原型数值。
2. **用户意图**：启用、长期上限、模式、保护及自动化偏好。意图不等于硬件已应用。
3. **执行状态**：未授权、请求中、已确认、失败、恢复中、恢复失败；附请求身份、能力和最后回读。
4. **业务模式**：自动、放电、充满、暂停、校准。过热、航海等待、未接电、不可用是有原因的实际状态，不能只用一个开关推导。
5. **采样质量**：支持、缺失、过期、权限错误、恢复未知；趋势和指标同时带时间及口径。

多入口请求串行化或明确取消替换。重复点击、晚到回调和重启不能覆盖较新的意图；校准、任务与人工动作的冲突需有可判断的结果。

### 4.2 功能与保护关系

- 无内置电池、硬件不支持、权限未就绪和控制工具冲突时，不写入充电设置；保留可读数据、设置和恢复入口。
- 未接电不能开始手动放电、充满或校准。拔电后的模式退出/中断要明确，不能保持“正在充电”的假状态。
- 校准运行时禁止直接改限充；新模式要求用户明确停止校准。无人值守任务的冲突策略见 BM1-F11。
- 航海只在支持设备且有效上下限存在时生效；低于20%时不因航海等待而阻止必要充电。不能因此绕过真实硬件保护。
- 热保护用于暂停充电，不能在没有证据时对原软件所有放电阶段套用同一规则。校准与热保护的精确优先级、传感器失败策略和恢复回差列入技术验证。
- “功能关闭”“系统已恢复”“电池已停止充电”分别展示；只恢复自身持有的变更，不能覆盖外部后续修改。

### 4.3 数据真实性

现有进程列表读取 `top` 的 power/CPU 影响指标，不是经验证的单应用瓦数。原型应用列表的 W 不能移植为生产单位；正式界面必须使用实际数据源对应的单位与名称。温度、健康度、适配器额定功率、每应用功耗和估算续航均需分别验证来源；不能按静态常量补齐。

已有电池历史为进程内采样，约5分钟间隔、最多72条的当前实现，不天然覆盖完整24小时或重启历史。趋势时间范围按实际覆盖显示，是否增加持久化与保留期在技术设计中说明，不虚构缺失区间。

## 5. 功能点

以下 `si.bm.*` 为**拟定原生可访问标识**，尚未加入代码或标注 JSON，不是当前可命中的 selector。

### BM1-F01 · 电池入口、三分区与设置路由

- **业务目的**：让读数、充电操作、趋势各有清楚位置，保留原产品入口。
- **使用者**：SuperIsland 本机用户；无电池设备可看不支持原因。
- **触发**：现有电池图标；概览/充电/趋势切换；电池内设置。预留 `si.bm.overview`、`si.bm.control`、`si.bm.trend`、`si.bm.settings-entry`。
- **流程**：打开电池 → 默认概览 → 切换分区 → 从模块内设置打开已有设置窗口并选中电池管理；关闭设置回到原模块。
- **规则**：统一齿轮仍进入通用；不创建第二个设置窗口或独立充电图标；切换页面不改变控制模式或长期偏好。
- **边界**：设置已打开其他菜单时正确切换；肩部/内嵌顶栏、窄窗口、VoiceOver、键盘和减少动态效果可用；既有音乐/通知等模块回归。
- **数据**：只增加当前展示分区等 UI 状态，读取共享电池服务。
- **验收**：两种齿轮分别到正确位置；三分区无截断/覆盖；重复开关设置无重复实例；所有入口反映同一上限与模式。

### BM1-F02 · 概览、详细仪表与指标质量

- **业务目的**：用户不用先进入设置就能看关键电池读数，同时可按需查看详细统计。
- **使用者**：有可读电池/适配器能力的本机用户。
- **触发**：灵动岛概览、设置仪表板、小工具选择及排序；预留 `si.bm.metrics`。
- **流程**：读取共享快照 → 展示电量/电源/当前状态 → 默认显示温度、功耗、最大容量、循环次数、预计续航、电压 → 设置中调整指标和查看电池/适配器细项。设备支持时提供电源/系统/电池流向；不支持时说明，不用固定箭头冒充真实流向。该细节已由v0.3模拟呈现，真实数据源仍待验证。
- **规则**：灵动岛最多展示适合尺寸的六项；同一字段在详细仪表和概览数值、单位和采样时刻一致。充电剩余时间、预计电池续航要按语义标注，不能混用。
- **边界**：不支持、未知和过期显示原因；无电池不展示伪电量；瞬时功耗接近零时不显示无穷大续航；权限失败不伪装为没有高耗能应用。
- **数据**：带来源/时间/质量的指标；容量设计值与最大值；当前和额定适配器值；进程影响指标及聚合口径。后台进程筛选与原生应用身份关联。
- **验收**：实际读数与独立系统来源对照；缺失字段保持未知；小工具增减排序生效；平均/即时模式给出正确时间窗口；不把 CPU/影响分数标 W。

### BM1-F03 · 电量趋势

- **业务目的**：理解近期充放电变化，不把目标上限当作当前电量。
- **使用者**：拥有历史采样的本机用户。
- **触发**：灵动岛趋势、6/12/24小时范围；预留 `si.bm.history`。
- **流程**：选择范围 → 过滤有效采样 → 绘制电量线与上限虚线 → 标明当前读数、覆盖时间和不足样本。
- **规则**：只绘制真实已有样本；不把应用重启后的缺口连成连续测量，不把上限变化画成实际电量变化；与刷新调度策略一致。
- **边界**：少于两点显示“样本不足”；设备/系统睡眠、时间调整和重启缺口明确；没有24小时数据时不声称完整覆盖。
- **数据**：采样时间、电量、来源/质量、控制上限；持久化和保留策略需在技术设计中确定并告知。
- **验收**：范围切换正确；控制上限变化仅影响参考线；当前电量读数与概览一致；缺口和空态可复现。

### BM1-F04 · 上限滑块、数字输入与低充电弹窗

- **业务目的**：直接在灵动岛调整上限，允许用户明确开启更低的限制。
- **使用者**：支持限充且授权就绪的用户。
- **触发**：充电页滑块、设置数字输入、“允许充电至低于80%”；预留 `si.bm.limit`、`si.bm.low-limit`。
- **流程**：拖动实时预览 → 松手提交；数字输入先草稿、点应用后提交。未允许低值时尝试低于80%，弹“低充电限值”，可取消或打开设置并聚焦低值开关。
- **规则**：默认允许80–100%；低值开启后的20–100%为已演示口径，原生按设备验证能力收敛，不默默接受硬件不支持的目标。拖动不直接改当前电量；校准时限充输入禁用。
- **边界**：取消保留原已应用值；超界/非数字拒绝；失败保留原生回读与失败原因；关闭低值开关而上限低于80%时先确认调整至80%。
- **数据**：草稿、请求目标、最后确认上限、低值允许标记、请求身份及回读结果。
- **验收**：80→90实时预览、松手生效、设置同步；80以下提示两条路径；开启后可设合法低值；实际电量不被滑块改写。Intel 的低值开关例外按第6.1节核实，不一概套用原型。

### BM1-F05 · 自动控制、放电、充满与暂停

- **业务目的**：按选定上限管理电量，并支持短期出行充满或临时停止充电。
- **使用者**：具备对应控制能力并已接电的用户；读取仍可在电池供电下使用。
- **触发**：灵动岛/设置的放电、充满、暂停、恢复自动；上限变化和自动放电开关；预留 `si.bm.mode`。
- **流程**：校验设备/电源/权限/冲突 → 提交意图 → 控制并回读 → 展示结果；自动放电开启且电量高于限值时放至限值，随后回到自动。
- **规则**：放电目标低于当前电量；充满以100%为临时目标并保持至断开电源；停止对应模式回自动。暂停使用临时目标并保留长期限值和低于80%开关；恢复后按原限值重评估，重复暂停按钮可恢复充电；临时暂停不能在重启后错误续跑。
- **边界**：未接电拒绝；Intel或硬件不支持的模式明确禁用；与校准冲突先确认；系统状态存在延迟时显示“正在同步”而非伪报完成。
- **数据**：长期限值、模式、临时目标、开始/结束原因、回读结果与恢复依据；临时状态不得与长期偏好混淆。
- **验收**：分别验证自动到限、超限自动放电、手动到限停止、充满后保持/拔电、暂停恢复；失败不能显示成功，重复动作不创建双重控制。

### BM1-F06 · 航海模式

- **业务目的**：通过回差减少接近上限时频繁充放电。
- **使用者**：支持航海控制的接电设备用户。
- **触发**：设置航海开关、下限；电量达到上下限。预留 `si.bm.sailing`。
- **流程**：充到上限 → 等待自然下降 → 到下限再充 → 循环；概览明确显示航海等待。
- **规则**：下限必须低于上限。低于20%不因航海等待阻止必要充电。原型70%下限是演示值；原软件精确参数语义与生产默认仍需核实。
- **边界**：上限等于最低可设值而无合法下限时不可启用，说明原因；Intel不支持；拔电、模式切换和校准时不残留旧等待锁。
- **数据**：启用、上下限、当前回差阶段、控制来源和回读。
- **验收**：上下限两端和区间内状态正确；手动改上限重新判断；低电量覆盖有证据；不存在上限20而下限19的静默非法状态。

### BM1-F07 · 过热保护

- **业务目的**：根据可信电池温度限制充电，避免状态显示与实际控制脱节。
- **使用者**：有受支持温度传感和充电控制的用户。
- **触发**：保护开关、阈值、温度变化；预留 `si.bm.heat`。
- **流程**：采样 → 判断保护 → 暂停充电并显示原因 → 达恢复条件后按之前有效模式重评估。
- **规则**：原型默认关闭、阈值35°C、25–50范围仅为候选演示；真实阈值、滞回和采样频率先验证，不用原型字段证明硬件安全。
- **边界**：传感器缺失/过期显示未知；不能把缺失温度当0°C；不能在恢复后复活已取消校准或旧临时模式；不能擅自改变KA1热保护。
- **数据**：温度值/单位/来源/时间、用户阈值、触发原因、恢复条件、暂停前模式。
- **验收**：升温触发、边界附近无异常抖动、降温恢复和传感故障均验证；实际充电停止/恢复独立回读。

### BM1-F08 · 五阶段校准

- **业务目的**：提供完整、可解释、可中止的校准过程。
- **使用者**：支持校准、已接电且授权就绪的用户；不支持设备禁用。
- **触发**：设置“开始校准”、定时/捷径校准；预留 `si.bm.calibration`。
- **流程**：确认 → 保存原限值 → 100% → 10% → 100% → 保持 → 原限值；当前阶段在设置和灵动岛状态中可见；成功完成才更新上次校准时间。
- **规则**：校准期间改模式先确认停止；中止后恢复保存的限值并核验。保持阶段及其时长按D2和第6.1节的版本证据确定，原型120分钟不能直接实施。取消确认不启动、不改状态。
- **边界**：识别macOS自身校准并解释临时超过限值的原因，不在系统强制阶段循环写入对抗；原软件1.39已声明此联动，原型未完整覆盖，已在v0.3补充模拟交互，仍待增量确认和原生验证。拔电、温度保护、关机/退出、权限失联、Intel切换、任务冲突和阶段超时分别处理；不得靠定时器假定真实电量达到目标。重启恢复策略须与D1及恢复义务一起核验。
- **数据**：校准ID、阶段、真实达到目标证据、保存的上限、开始/结束/中止原因、保持时钟、最后完成时间和恢复结果。
- **验收**：五阶段逐项对照真实读数；取消、每阶段中止、拔电和异常恢复可复现；未完成不写“上次校准成功”；恢复失败仍可重试。

### BM1-F09 · 睡眠行为与保持唤醒协调

- **业务目的**：明确睡眠/显示/合盖期间的充电行为，同时保护已有任务和其他功能。
- **使用者**：有对应能力的本机用户。
- **触发**：照原样继续 / 睡眠时停充 / 上限前阻止休眠三选一；退出停充、屏幕关闭、合盖锁屏。预留 `si.bm.sleep`。
- **流程**：选择策略 → 真实电源/睡眠事件判断 → 与自有保持策略协调 → 执行可支持行为并回读。
- **规则**：睡眠停充与上限前保持互斥；达到目标或拔电后结束本功能不再需要的保持。不得取消KA1的其他任务或全局断言，关闭电池控制不等于关闭保持唤醒。
- **边界**：真正睡眠、显示屏关闭、锁屏和合盖要区分；普通保持不能冒称合盖支持；退出停充必须说明持续性、重新启用路径及硬件边界后才允许开启。
- **数据**：睡眠策略、显示/锁屏偏好、控制所有权、自有保持租约、系统回读、与KA1的协调结果。
- **验收**：三策略互斥；达到目标/拔电释放自身保持；KA1仍有任务时不被本功能终止；没有合盖能力时不出现可成功执行的假入口。

### BM1-F10 · 能源模式与高耗能应用

- **业务目的**：让用户按电源环境管理能耗，并理解应用影响。
- **使用者**：支持对应macOS能源模式的设备用户。
- **触发**：低功耗/高功率模式、后台仪表更新、应用阈值及包含后台进程；预留 `si.bm.energy`。
- **流程**：选从不/始终/仅电池/仅适配器 → 校验设备支持 → 应用并回读；筛选条件作用于同一进程指标列表。普通可退出应用提供“退出”动作，按应用身份正常请求退出；后台服务/系统进程不提供强制结束。v0.3需求稿中的动作仅模拟；原生按钮经确认发送正常退出请求，未保存内容由目标应用自行确认，不强制结束。
- **规则**：两种能源模式的组合及系统优先关系需核实；不支持高功率模式不能显示已启用；后台更新复用现有节能刷新调度，不维持无意义高频轮询。
- **边界**：系统设置被外部修改时刷新事实而非盲目写回；进程退出、同名进程、无权限和采样缺失处理正确；W、CPU%与影响分数不得混用。
- **数据**：每种模式的选择、实际系统状态、能力、应用/进程身份、指标口径、时间窗口、阈值。
- **验收**：接电/拔电切换符合选择；系统回读和UI一致；筛选、后台进程与仪表列表同步；权限失败不是空列表成功。

### BM1-F11 · 定时任务、模板、补做与历史

- **业务目的**：在既定时间执行充电操作，并能追溯是否实际执行。
- **使用者**：需要充满、上限调整、放电或校准自动化的用户。
- **触发**：新建/编辑/删除/启停任务，时间到达，模板，补做开关；预留 `si.bm.schedule`。
- **流程**：配置名称、动作、目标、时间、重复 → 校验保存 → 到时运行 → 记录结果；模板可编辑；删除与清空历史要求明确确认。
- **规则**：支持一次、每天、每周、每两周、每月以及原软件已有的每年；年度间隔已在v0.3呈现并验证。初始时区为Asia/Shanghai并显式展示。周一05:00充满、周六07:00充满、每月/每两周校准为模板主题。每月无同日的月末处理和夏令时/时区迁移须在原生设计中明确。
- **边界**：睡眠/关机错过后按补做偏好判断并去重；校准冲突在有人操作时可“忽略 / 停止校准后执行”。无人值守时不得弹窗后假报完成，其默认处理保持待确认，不能自动中断校准。无权限/不接电/系统不支持明确记录未执行；不把请求受理当完成。
- **数据**：稳定任务ID、动作/参数、时区/重复、启用、最近与下一次计划时间、触发实例ID、真实执行结果/失败/跳过原因和历史保留策略。保留期限在正式实施设计中明确。
- **验收**：CRUD、模板、重复、月末、跨时区、补做和重启去重可复现；同一计划实例最多生效一次；历史区分成功/失败/跳过/待确认。

### BM1-F12 · 12项苹果捷径

- **业务目的**：让用户从系统自动化调用同一电池能力。
- **使用者**：已启用系统捷径并具备相应控制能力的用户。
- **触发**：充满、暂停、放电、开始校准、设置上限、取电量、取上限、取状态、取温度、设置MagSafe LED、低功耗模式、高功率模式；预留 `si.bm.shortcuts`。
- **流程**：接收输入 → 与UI同一校验/权限/冲突逻辑 → 执行/查询 → 返回结构化真实结果；需要确认时返回待确认或明确失败，不伪造后台成功。
- **规则**：查询不触发写入；参数范围、支持枚举和单位明确；校准、低于80%、设备不支持等规则不能从捷径绕过。
- **边界**：App未运行、锁屏、无人值守、权限撤销、超时和重入分别测试；不得仅做页面里的测试器就声称已注册系统捷径。
- **数据**：动作名、参数、请求身份、受理/应用/确认/失败状态、返回值/单位/质量。生产Intent名称和提取元数据见源码；真实系统逐项执行仍待验收。
- **验收**：在真实快捷指令App中逐项调用12个能力，核验参数、结果及UI同步；本地原型的JSON返回只算设计验证。

### BM1-F13 · 显示偏好与仪表配置

- **业务目的**：在有限空间保留用户关心的信息，不新增图标入口。
- **使用者**：使用电池模块的本机用户。
- **触发**：小工具选择/排序、百分比、透明度、启动显示、现有入口统计与右击选项；预留 `si.bm.display`。
- **流程**：修改偏好 → 保存 → 同一模块即时预览；重置/清除统计项不清除设备历史或控制权限。
- **规则**：概览最多六项并与详细仪表同源；图标样式/统计/右击映射原有电池入口，禁止恢复独立充电图标。启动显示仅影响展示，不代表启动控制。
- **边界**：无选中指标时清楚展示空态；隐藏面板内容后仍有设置入口；不能隐藏恢复错误；系统主题、可访问性和禁用状态满足项目现有规范。
- **数据**：指标稳定键和顺序、显示偏好、刷新间隔、右击动作；不存重复业务状态。
- **验收**：增减排序反馈到概览与详细仪表；关闭/重开偏好保留；隐藏百分比不改变上限；右击不绕过控制校验。

### BM1-F14 · 硬件百分比、Intel与MagSafe

- **业务目的**：在支持设备上提供完整能力，同时明确不适用分支。
- **使用者**：具备相应传感器、控制模式或MagSafe硬件的用户。
- **触发**：硬件百分比指标、Intel模式、LED颜色、随限制指示、放电闪烁；预留 `si.bm.hardware`。
- **流程**：能力探测 → 展示可用项 → 用户选择 → 应用/回读；模式切换中止不兼容流程前需确认。
- **规则**：硬件电量只作统计显示，限充按macOS电量口径；官方1.39说明已移除控制源切换，v0.3已移除原型中的控制源开关，改为统计读数。Intel分支不支持的放电/航海/校准禁用；LED选项按支持范围提供，不能用静态点颜色当真实硬件结果。
- **边界**：无MagSafe、设备型号未知、SMC键不可读/不可写、系统升级和重启均需验证；不按CPU架构名就推断全部能力。
- **数据**：每项能力及探测证据/版本、硬件/系统读数、选择与实际状态、失败原因。
- **验收**：代表性硬件和不支持设备分别验证；切换模式不留下校准和旧限值；不能把Intel或Apple Silicon一种设备结果推广为全平台支持。

### BM1-F15 · 总开关、权限、冲突与恢复

- **业务目的**：让用户能理解控制是否真正生效并安全停止，避免多个工具同时写电池。
- **使用者**：所有用户；安装/授权由系统要求的身份完成。
- **触发**：启用/关闭、权限缺失、控制工具冲突、失败重试、恢复默认和退出；预留 `si.bm.master`、`si.bm.recovery`。
- **流程**：读取能力/权限/现状 → 明确用户意图 → 执行自身控制 → 回读；关闭后停止新请求、恢复自身持有的变更 → 成功或保留恢复义务及重试。
- **规则**：首次和应用重启按D1自动检查、启用并提示；存在未解决恢复义务时先显示受阻和恢复路径，不能自动建立相反控制；既有电池模块显示开关与充电控制开关要明确区分。总开关不自动安装helper、不替用户授予权限；诊断不得输出令牌、私人正文或不必要硬件序列号。
- **边界**：恢复时外部已改变设置、helper失联、应用崩溃、系统关机、晚到回调、部分恢复失败都须处理；不停止AlDente或改其配置来消除冲突。恢复默认不删除任务/历史，除非用户明确选择对应操作。
- **数据**：启用意图、自有控制快照/所有权、恢复责任、实际回读、错误/冲突、授权能力和请求身份；与来源系统事实分开。
- **验收**：未授权不能成功执行；冲突阻止写入；关闭、崩溃后恢复及重试用真实系统结果验证；开关关闭不等于已恢复，恢复未知时不报成功。

### 6.1 官方资料核对发现的差异（新增证据，不回改已确认快照）

2026-10-29 补查官方来源后确认，包内旧文案不能单独作为当前功能开关存在或执行行为的证明：

- [官方1.39.4发布说明](https://github.com/AppHouseKitchen/AlDente-Battery_Care_and_Monitoring/releases/tag/1.39.4) 汇总1.39变更：硬件百分比改为统计项，限充使用macOS电量口径；Intel低于80%的开关有版本例外。按设备/版本核实后修正原型。
