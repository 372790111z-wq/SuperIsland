## 2. 目标、范围与补充决定

用户开盖回来时，可以知道这次合盖多久、SuperIsland 实际保持多久、哪些任务已经完成、还有哪些未结束，以及保持是否释放、Mac 是否真正睡过。**回顾展示已有事实，不参与任务结束、保持或休眠的决策。**

本版包含独立回顾弹窗、现有杯子菜单的“最近一次合盖回顾”、自动显示偏好、时间线与统计说明。只提供最近一次回顾，无历史中心、导出、云同步、正文查看或工具调用榜单，不新增菜单栏图标。

### 2.1 已确认 HTML 行为

| 内容 | 规则 |
| --- | --- |
| 自动展示 | MacBook 实际开盖并解锁后，同一合盖周期最多自动展示一次 |
| 展示条件 | 自动显示开启，且该周期有实际保持、已识别用户任务或异常；普通无任务合盖不打扰 |
| 概览 | 合盖时长、保持运行时长、任务状态数量、保持释放与系统休眠结果 |
| 任务 | 来源、匿名任务编号、状态和可信时间；不展示真实任务正文 |
| 未结束 | 运行中、等待确认、状态未知分别显示，不算已完成；关闭窗口不停止任务 |
| 异常 | 任务失败、恢复未确认、记录不完整明确区分，不虚报恢复或实际休眠 |

| 关闭与重开 | × / Esc 只收起回顾，不显示取消文案；现有杯子菜单可重开最近一次 |

| Mac mini | 无机盖事件，不触发开盖回顾；无机盖能力时最近回顾入口置灰 |

### 2.2 随整份 PRD 已确认的补充边界

原型未完整演示以下生命周期边界，已由用户随整份 PRD 确认：

1. **开盖时点快照**：本次实际开盖是统计截止点，状态标明“截至本次开盖”。之后的新任务或任务变化不改写这份历史回顾。
2. **总开关优先**：保持唤醒总开关关闭时不自动弹出，自动显示偏好保留；可手动查看已保存摘要。重新开启只影响新周期，不补弹旧回顾。
3. **最小本机留存**：只保留当前未闭合周期的必要摘要和最近一次完成周期；新周期完成后替换上一份。关闭自动显示不删除最近记录，不提供长期历史。
4. **重启不补弹**：重启后可手动查看最近摘要，但不补弹旧回顾；跨进程存在缺口的周期明确标为信息不完整。

## 3. 统计与状态口径

### 3.1 周期与两项时长

- 一个周期从真实机盖由开变关开始，到随后由关变开结束。解锁只影响展示时机，不延长合盖时长；维护唤醒、网络唤醒和屏幕亮起都不等于开盖。
- 合盖时长包含任务执行、释放等待和实际睡眠。持续时长采用可跨睡眠的单调时间证据，墙上时间用于显示时间点；跨天、改系统时间或时区不能造成负数或虚假时长。
- 保持运行时长是**该周期内本功能实际生效的保持区间并集**，裁剪到关盖与开盖之间；并发任务不重复计时，最后任务终结后实际仍保持的 30 秒等待也计入。
- running、保持请求、辅助程序已注册均不能单独证明实际保持。缺少所需合盖支持状态或关键区间边界时，标记不完整并显示“—”，不能把已知部分当成完整值。
- 该指标不表示 CPU 工作时长、各任务耗时之和或节省时间。明确没有保持才显示 0；未知不补零。
- 使用分 / 秒，长时段可用小时 / 分钟，不向上取整虚增；保持时长不得大于合盖时长。

### 3.2 用户任务、分类与去重

- 纳入关盖时已开始但未明确终结的用户任务，以及闭盖期间新开始的任务；不纳入关盖前已结束或开盖后才开始的任务。
- 复用 KA1 已规范化的来源、接入通道、会话和任务身份。同一任务的 hook / notify / 状态刷新不重复计数；不能跨来源只按相同 taskID 合并，不能因标题相同合并父子任务。
- 工具调用不单独算用户任务。只有来源提供可靠明确分类时才另列后台检查；不得读正文、按标题或“0 tools”猜测。
- 类型待确认记录单独注明，不混入“已完成”，也不制造所有记录均已识别的印象。展示分类不改变 KA1 保持守卫：已有未终结执行仍按原规则处理。
- 只有进程、用量或不完整身份的来源不能据此捏造任务；未接入和暂缓接入来源不生成假记录。
- 清单仅显示来源、周期内稳定匿名编号、状态及可信时间；桌面端与 CLI 沿用原有独立来源边界。

| 状态 | 计入“已完成” | 展示含义 |
| --- | --- | --- |
| completed | 是 | 明确完成，不代表其他任务结束或已经休眠 |
| failed | 否 | 单列失败；是终结状态，不改变 KA1 原有释放判断 |
| cancelled | 否 | 单列取消，不与成功混算 |
| running | 否 | 运行中，实际保持另看电源事实 |
| waiting | 否 | 等待确认，已开始任务按 KA1 继续保持 |
| unknown | 否 | 最新状态无法确认，不按失联、超时或界面消失判为完成 |

用户任务总数等于六类数量之和，也等于去重后的用户清单项数；后台检查和类型待确认记录另列。关闭窗口、切换偏好、重看回顾都不能生成终结事件。

### 3.3 保持与实际休眠分别判断

| 事实 | 展示 |
| --- | --- |
| 开盖时仍实际保持且有未结束任务 | 继续保持，并给出未结束任务或未知状态 |
| 任务均已终结，但开盖时仍在 30 秒等待内 | 等待释放，注明开盖时尚在等待，不当作异常 |
| 普通保持与所需合盖辅助保持均确认释放 | 已自动释放，或对应的已确认结束原因及时间 |
| 普通保持结束，但辅助程序 / 系统恢复未确认 | 释放尚未确认 |
| 本周期未实际启用保持 | 本次未启用保持，不能冒称自动释放 |
| 只有休眠请求被受理 | 休眠尚未确认 |
| 有可信实际睡眠证据 | 已确认休眠，并给可信时间 |
| 有未结束任务且没有睡眠记录 | 未休眠 · 还有未结束任务 |
| 记录缺口导致无法判断 | 无法确认，并说明信息不完整 |

实际睡眠需由可信睡眠 / 唤醒记录与跨睡眠时钟证据核验；单一请求返回、will-sleep 通知、App 卡住或一段无采样均不够。维护唤醒可以证明此前睡过，但不触发回顾。

自身释放与全局是否允许休眠分开。没有证据时不把未休眠归咎于某个外部 App；确有系统或其他工具限制时可说明，不自动停止它。

手动保持、手动停止、保护停止和自动任务全部终结按真实原因区分。任务运行与实际保持不能合并为一个状态：保护已停止保持时，不得把仍运行的任务显示为完成，也不能误报继续保持。

## 4. 功能点

### KA2-F01 · 合盖周期与自动展示

- **业务目的**：在用户回到 Mac 时展示对应周期，避免普通唤醒、锁屏和重复事件打扰。
- **使用者**：使用保持唤醒的 MacBook 用户；无机盖的桌面 Mac 不触发。
- **触发**：实际开盖、已解锁、总开关与自动显示均开启，且该周期有保持、任务或异常。预留原生标识 si.ka.recap。
- **流程**：识别关盖周期 → 持续汇总最小事实 → 实际开盖确定截止点 → 等待解锁 → 判断条件 → 自动展示一次。
- **规则**：以稳定周期身份防重复；实际可见才记为已展示，不能在锁屏等待时提前消费。自动展示不抢输入焦点、不强制切换空间，不额外发送系统通知。
- **边界**：维护 / 网络唤醒无弹窗；锁屏期间连续多周期，解锁后只考虑最近一次符合条件的完整周期，不排队弹旧窗口。Mac mini 不新增合盖授权入口。
- **数据**：周期身份、关盖 / 开盖时间、设备能力、锁定状态、偏好、展示标记及质量；不需要正文或硬件序列号。
- **验收**：同一开盖事件重复到达只显示一张；锁屏不露清单，解锁最多一张；闭盖维护唤醒不触发；普通无任务、无保持、无异常的开盖不弹。

### KA2-F02 · 时长概览与状态汇总

- **业务目的**：两项时长和数量可以核对，不把并发时间、工具调用或未知记录算成成果。
- **使用者**：自动或手动打开回顾的用户。
- **触发**：回顾打开、汇总可用。预留 si.ka.recap.metrics、si.ka.recap.summary。
- **流程**：读取周期摘要 → 按第 3 节计算时长与状态数 → 显示区间、两项时长及非零状态徽标；缺少记录显示未知。
- **规则**：实际区间取并集并裁剪；数量与全清单一致；终结后的保持等待计时，但不算另一项任务；失败、取消与完成分别显示。
- **边界**：起止或保持边界缺失不补零；跨天、超过 24 小时、系统调时仍正确。纯手动保持可以有时长而任务为 0，不生成假任务。
- **数据**：周期起止、实际保持区间、质量、已识别任务计数与状态分布；时长均为派生值。
- **验收**：合盖 19 分钟，保持区间 [0,600] 与 [300,840] 秒的并集为 14 分钟。已知无保持显示 0、未知显示“—”；每个状态数量可在清单逐项核对。

### KA2-F03 · 任务清单与可靠分类

- **业务目的**：知道哪项已结束、哪项仍需处理，避免正文泄露和后台检查混数。
- **使用者**：有已接入来源事件的用户；未接入来源不伪造任务。
- **触发**：周期存在任务或辅助记录。预留 si.ka.recap.tasks、si.ka.recap.auxiliary。
- **流程**：按既有身份去重 → 分为用户任务、明确后台检查、类型待确认 → 用户任务显示来源 / 编号 / 状态 / 可信时间 → 辅助记录按需展开。
- **规则**：按周期内首次出现顺序稳定编号，重开不变；使用已有图标，缺失时文字占位。本版不读、不存、不提供展示真实标题、提示词、回复、工具参数或消息摘录的开关。
- **边界**：父子关系不代表重复；缺少分类需明示，不能按标题推断。长清单可以滚动，但数量覆盖整个周期而非仅可见行。
- **数据**：来源、匿名任务身份、周期内编号、状态、可信时间及可靠分类标记；不创建第二套执行状态机。
- **验收**：2 条清单对应 2 项完成；一完成、一等待、一运行总数 3、完成数 1；后台检查分列、未知分类明示；跨源同 taskID、父子及 hook / notify 重复无误合并或重复计数。

### KA2-F04 · 保持、休眠与异常

- **业务目的**：明确任务结束、保持释放、真正休眠的区别，异常时给出可处理的信息。
- **使用者**：核对本次电源结果的用户。
- **触发**：周期存在保持 / 释放 / 睡眠事实或数据缺口。预留 si.ka.recap.power、si.ka.recap.notice。
- **流程**：分别读取保持与系统证据 → 显示两行独立结论及可信时间 → 异常或缺口说明原因，指出已有“保护与恢复”或任务来源管理入口。
- **规则**：遵循第 3.3 节；只有证据支持才显示已释放 / 已确认休眠。新任务取消释放时不保留旧成功结论；开盖后的新保持不倒写本次结果。
- **边界**：辅助恢复失败、任务失败、信息不完整分别显示。仅受理请求显示休眠尚未确认；手动 / 保护停止不能因此触发或补发睡眠请求。
- **数据**：实际保持、辅助 / 系统恢复确认、原因及时间、请求受理、真实睡眠 / 唤醒与时钟证据、质量；只消费 KA1 事实。
- **验收**：完成并睡眠、未结束保持、恢复未确认、仅请求受理、记录缺失均正确。回顾开关、打开或关闭不改变断言、租约、任务终结或睡眠请求次数。

### KA2-F05 · 时间线与统计说明

- **业务目的**：按需解释时长差异、释放等待和任务数，默认弹窗保持简洁。
- **使用者**：需要核对具体结论的用户。
- **触发**：点击本次时间线 / 统计说明。预留 si.ka.recap.timeline、si.ka.recap.explanation。
- **流程**：默认收起 → 展开相应内容 → 查看真实节点与统计定义 → 再次收起。
- **规则**：按实际事件顺序展示；同类重复刷新不刷屏；维护唤醒不分裂周期；说明与第 3 节一致，不把保持运行称为 CPU 工作时长。
- **边界**：未知时间标未知，只有受理时不补系统睡眠节点；多次真实睡眠 / 维护唤醒可摘要显示，不能冒称整段连续睡眠。窄屏同时展开仍无横向溢出，不遮关闭入口。
- **数据**：本周期最小事件摘要、可信时间与质量；不展示原始日志、私有路径、正文或凭据。
- **验收**：能解释 19 分钟合盖与 14 分钟保持；两项说明可分别 / 同时展开；概览、任务、时间线和电源结果时间与数量一致。

### KA2-F06 · 关闭、重开与原生呈现

- **业务目的**：随时收起和找回回顾，不影响任务或当前工作。
- **使用者**：正在输入、使用全屏 App 或需要重看结果的用户。
- **触发**：自动展示、× / Esc、杯子菜单“最近一次合盖回顾”。预留 si.ka.recap.close、si.ka.recap.last。
- **流程**：独立面板显示 → 关闭立即隐藏，不显示取消提示 → 从既有杯子菜单重开最近摘要；手动打开才按用户意图给窗口焦点。
- **规则**：关闭不停止 / 完成 / 取消任务，不重置保持或偏好、不标记系统已恢复。手动重开不受“已自动展示一次”限制；无最近记录时入口置灰。Esc 在回顾自身接收键盘事件时生效，不安装全局 Esc 拦截去影响其他 App。
- **边界**：不创建或前置设置窗口、不新增菜单栏图标；当前活动显示器可见区域只显示一张，不置于实体刘海遮挡区、不强制移屏。总开关关闭仍可查看已有摘要，相关偏好按 MS1 置灰。
- **数据**：最近摘要引用、面板可见状态、展示来源和焦点意图；不新建任务、不读正文。
- **验收**：其他 App 前台时不带出设置；× / Esc 及时关闭无提示；手动重开内容一致。深浅色背景不透底、文字可读，键盘 / 辅助功能可用，长列表不裁切控件。

### KA2-F07 · 自动显示偏好

- **业务目的**：控制打扰程度，并可从既有入口恢复自动回顾。
- **使用者**：MacBook 用户。
- **触发**：回顾底部或杯子菜单的开盖自动显示选项。预留 si.ka.recap.auto。
- **流程**：首次默认开启 → 任一入口切换保存 → 两处同步 → 后续新周期按偏好展示；关闭后仍可手动查看最近一次。
- **规则**：一个本机布尔真源，跨重启保留。不启用 KA1 总开关，不改来源连接、合盖授权、30 秒释放或完成通知偏好。
- **边界**：总开关关闭时自动展示停止，偏好保留且按 MS1 置灰；重新开启不补弹旧周期。保存失败保留原有效值并说明未保存，不假称已记住；无机盖设备不提供可生效的开盖开关。
- **数据**：自动显示布尔偏好及读写结果，默认 true；HTML localStorage 仅演示，不作为原生配置路径或跨机真源。
- **验收**：弹窗 / 菜单双向同步、关闭后新开盖不弹、手动仍可看、重启保留；写入失败不矛盾；总开关 off / on 不篡改原选择。

### KA2-F08 · 最小记录、完整性与隐私

- **业务目的**：跨任务完成、系统睡眠和重启仍有可信回顾，不依赖测试进程或无限行为日志。
- **使用者**：本机用户，无云端共享或管理角色。
- **触发**：关盖、任务 / 保持关键状态变化、睡眠 / 唤醒、开盖汇总、读写与恢复。
- **流程**：App 自有生命周期记录最小事实 → 原子保存当前周期 → 开盖形成摘要 → 替换最近一次 → 重开只读摘要；缺口进入信息不完整。
- **规则**：只保留当前未闭合周期和最近一次完成摘要。不依赖 Codex 工具进程、外部 shell 监测器或限时验收请求；现有 15 分钟 opt-in 文件不能充当生产记录唯一真源。记录失败不阻碍 KA1 保持 / 安全释放。
- **边界**：App 中断、截断、容量到限或写入失败必须保留质量标记，不用旧周期冒充本次，不用重启清状态冒充完成。缺开盖边界时不能用重启时间假作开盖；正常退出和崩溃分别验证。
- **数据**：周期、最小时间 / 区间、来源与匿名任务身份、状态 / 分类质量、保持 / 恢复 / 休眠事实、展示标记和完整性。不保存标题、正文、transcript、工具参数、剪贴板、凭据、完整私有路径或硬件唯一标识；不上传，使用本机私有目录和文件保护。
- **验收**：真实任务结束后 App 继续记录，睡眠后摘要可恢复；重启只显示可恢复部分且不补弹。仅保留约定记录，无无限追加；损坏或来源不明的数据不产生成功结论，不影响保持策略。

## 7. 数据边界与不变式

下列为逻辑语义，实施时优先复用现有结构，不要求新增公网 API、数据库或 helper 权限。

| 数据组 | 最小内容 | 不变式 |
| --- | --- | --- |
| 周期 | cycleID、真实关盖 / 开盖、设备能力、单调与显示时间、质量 | 一次关盖至开盖一个周期，维护唤醒不分裂 |
| 保持 | 实际区间、必要辅助状态、释放原因和确认 | 并集裁剪，不以 requested / running 代替 actual |
| 任务 | 既有身份、来源 / 通道、状态、可靠分类与时间、编号 | 跨源不误合并，重复事件不增数，界面不能结束任务 |
| 休眠 | 请求受理与实际证据分开，时间和质量 | 不因请求成功、采样缺口或墙上时间跳变生成已睡 |
| 展示 | 自动偏好、最近摘要、每周期展示标记、窗口状态 | 重开不改任务 / 电源，新周期不复用旧成功 |
| 留存 | 当前未闭合周期、最近一次完成摘要、原子写入与质量 | 本机最小摘要，不无限追加日志，不依赖测试记录 |

迟到事件仅在身份、发生时间、周期归属均可信时补齐；无法归属标记缺口，不用开盖后新事件回填虚假的闭盖完成或释放。制作摘要时不阻塞原有任务 / 电源事件处理。
