## 2. 目标与范围

用户在“截图挂绳”和“保持唤醒”设置页顶部，均能通过与“窗口增强”一致的总开关控制整个功能，不必寻找分项开关，也不必依赖菜单栏才能停止功能。

本轮包含：

1. 截图挂绳新增“启用截图挂绳”总开关。
2. 保持唤醒复用已有“启用保持唤醒”开关，将其移到状态卡和三个管理分区上方；不增加第二个业务总开关。
3. 关闭后设置仍然显示，依赖启用的控件置灰且不可操作；重新开启保留原分项选择。
4. 两个独立菜单栏图标继续保留，菜单与设置共用同一状态；关闭时仍有重新开启入口。
5. 模块关闭、系统设置恢复、恢复失败重试，以及重新开启和重启的边界。

本轮不包含“清空复制的图片”、其他图片清理、来源适配扩展、辅助程序权限扩展、窗口增强行为修改或安装分发。不得改变原始图片、录屏、系统剪贴板内容、现有暂存架、Chrome / 设置窗口移屏行为。保持唤醒原有来源数量、可信事件、等待与未知处理、保护策略、30 秒自动释放和合盖完成后的收尾规则，继续按 KA1 执行。

## 4. 功能点

### MS1-F01 · 两页顶部总开关与关闭显示

- **业务目的**：提供统一、直接、随时可见的模块控制，避免总开关埋在分区内或与子开关混淆。
- **使用者**：使用 SuperIsland 设置的本机用户；查看和切换普通功能总开关不引入新的管理员授权。
- **触发**：打开设置侧栏对应页面，或从独立菜单进入设置；点击顶部 Switch。截图总开关预留 `si.sc.master`；唤醒复用 `si.ka.master`。标识须在原生实现后核验，不提前建立假 selector。
- **流程**：页面标题 → 顶部总开关卡 → 状态说明 → 分项设置。保持唤醒的“运行策略 / 任务来源 / 保护与恢复”放在总开关下方，切换分区不创建或替换总开关。
- **规则**：关闭后下方内容保留在原位置，依赖模块启用的参数和操作控件置灰并禁用；分区导航允许只读查看。关闭、恢复失败等状态仍清楚可见。必要的系统恢复 / 重试入口不随设置组禁用。重新开启恢复原选择与当前分区，不能把原分项全部改为开启。
- **边界**：窄窗口、滚动、键盘操作、VoiceOver 和减少动态效果均应可用。禁用控件不能通过快捷键或无障碍动作修改参数；总开关及恢复入口仍可到达。页面关闭、重开、切换分区不能改变模块状态。
- **数据**：复用模块的启用意图、实际运行 / 恢复状态与已有偏好；页面不另存第二份业务启用状态。当前管理分区只属于界面选择，不作为模块是否启用的依据。
- **验收**：两页各只有一个总开关，布局与窗口增强一致；正常关闭后分项仍可见但不能操作；保持唤醒切换三个分区仍能看到同一总开关；重开分项值与原选择一致；本轮不出现“关闭后仅剩标题和开关”的折叠效果。

### MS1-F02 · 截图挂绳关闭、保留与重新开启

- **业务目的**：一次停止挂绳的接收与展示能力，同时保留用户已经收集的内容和配置。
- **使用者**：使用截图挂绳的本机用户，包括已有卡片、已配置监听和已明确启用系统接管的用户。
- **触发**：设置页“启用截图挂绳”或独立挂绳菜单中的同一开关操作。
- **流程**：关闭时停止新文件监听、图片剪贴板接收、自动露出和挂绳展开快捷键响应，收起挂绳；若持有系统截图 / 录屏接管，则按 SC1 恢复与回读。重新开启时按保留的分项选择重新建立监听基线，恢复可用的普通入口。
- **规则**：总开关不改写 `watchEnabled`、`clipboardEnabled`、全屏显示、卡片大小等已有分项值。关闭不删除、移走或清空卡片、托管内容、外部原件及系统剪贴板。保留两个图标中的挂绳图标，但关闭时不能借菜单、快捷键、悬停或拖入继续接收 / 展开内容。已接管的系统设置恢复后，再次开启总开关不自动重新接管，仍需用户主动执行原有接管流程。
- **边界**：关闭时没有内容、目录不可访问或系统接管未开启，仍能停止普通能力；没有实际接管就不写系统设置。关闭期间的文件与剪贴板变更不因重开而批量补录，沿用 SC1 新内容基线与去重规则。处于编辑或文件写入中的用户内容不得被截断或删除，关闭后的晚到回调不得重新拉起挂绳或重复入列。恢复冲突与失败按 MS1-F05 处理。
- **数据**：新增一个可持久化的模块总开关；保留既有分项、项目列表、文件所有权、书签、快捷键偏好及系统接管恢复快照。存储位置与命名在实现阶段沿用项目约定，不形成第二套图库。
- **验收**：先设置一项开启、一项关闭并保留三张图片；关闭后新增截图 / 复制图片均不进入挂绳，快捷键不展开，原内容和文件仍在；重新开启保持原分项值且不重复导入旧内容。关闭过总开关后重启仍关闭；原来开启且权限允许时按原分项恢复，系统接管仍不自动重启。

### MS1-F03 · 保持唤醒复用总开关与释放

- **业务目的**：把已有保持控制放在页面最直接的位置，保证关闭后的真实电源效果与界面一致。
- **使用者**：使用自动或手动保持的本机用户；MacBook 和 Mac mini 共用普通总开关，合盖能力仍按硬件与 KA1 授权边界区分。
- **触发**：页面顶部“启用保持唤醒”、独立唤醒菜单及现有停止 / 自动模式入口；复用 `si.ka.master` 与现有服务状态。
- **流程**：关闭总开关后停止本功能的普通 / 显示保持请求，结束旧手动计时及其自动恢复路径，释放本功能合盖租约并等待系统设置恢复结果；总开关以下的状态卡、分区和设置继续显示。重新开启自动模式时重新判断已接入来源和未结束任务；手动模式不续跑旧计时，等待“开始”。
- **规则**：只保留一个业务总开关，不在三个管理分区或菜单创建独立且可能失步的开关状态。手动关闭优先于运行中任务，但不取消外部任务、不发完成提醒、不把未知改为完成，也不主动请求系统立即睡眠。明确终结后的 30 秒释放与合盖收尾仍按 KA1 执行；手动关闭不等待该 30 秒。再次开启仍遵循低电量、仅接电、低电量模式与热保护等原有规则。
- **边界**：关闭不卸载已有来源 hooks、不删除配置、不撤销已授予的辅助程序授权；已连接来源可继续提供必要状态元数据，但其事件不能越过关闭状态重新取得保持。总开关不能替代“接入来源”或“授权合盖”确认；关闭状态下分区里的新增接入 / 授权等操作随设置组禁用，已有连接和授权只读展示，必要恢复动作例外。Mac mini 不显示不适用的合盖操作；其他应用持有的断言不属于本功能，不能宣称已解除全系统所有保持。
- **数据**：复用现有启用意图、模式、实际保持、未结束任务、保护状态、手动 / 暂停期限、合盖租约、恢复结果及来源连接；不新增第二套任务聚合与超时策略。App 重启时总开关关闭，旧计时不恢复。
- **验收**：自动任务运行时主动关闭，总开关关闭且本功能断言和合盖限制按恢复结果释放，外部任务继续存在；后续事件不能自动开启。重开自动模式时有未结束任务则按原规则保持，无任务则等待；手动重开不自动续跑旧计时。App 重启仍关闭，来源配置和授权保留；原有真实根 / 子任务聚合和完成后自动释放回归通过。

### MS1-F04 · 独立图标、菜单与设置同源

- **业务目的**：保留用户已选择的独立快捷入口，并保证用户能从任一入口理解和改变同一个模块状态。
- **使用者**：使用独立挂绳 / 唤醒图标或原 SuperIsland 菜单的本机用户。
- **触发**：打开两个独立菜单、点击启用 / 关闭、选择“打开设置”，以及设置页总开关状态变化。
- **流程**：菜单读取同一模块状态，显示“已开启 / 已关闭 / 正在恢复 / 恢复失败”及适用动作；切换后设置立即同步。关闭时保留图标与“启用…”和设置入口，从菜单重开仍恢复原偏好。
- **规则**：不移除独立图标、不新建额外图标；既有 SuperIsland 菜单入口保留。图标可以弱化，但必须有文字或可访问名称说明关闭状态；不能仅靠颜色。挂绳“展开 / 收起”等依赖启用的动作在关闭时不可执行；恢复失败时重新启用遵循 MS1-F05，不通过菜单绕过恢复检查。
- **边界**：菜单处于打开状态时设置变化也应更新；快速重复操作、设置窗口已打开或关闭后再打开，均不能产生第二个运行实例、重复监听或两份计时。菜单不能因模块关闭而失去重新开启入口。
- **数据**：共享模块状态快照、恢复结果及动作可用性；菜单只读映射服务状态，不自行持久化总开关。
- **验收**：分别从菜单和设置关闭 / 开启，两处与独立图标状态始终一致；关闭后两个图标均保留；菜单能重开并定位对应设置页，其他依赖动作不能绕过关闭状态。

### MS1-F05 · 系统恢复、失败反馈与重试

- **业务目的**：保证界面不把“请求关闭”冒充“系统设置已恢复”，并在分项禁用后仍留有可用恢复路径。
- **使用者**：总开关关闭时持有截图接管或合盖保持等系统设置的用户。
- **触发**：关闭总开关、已有恢复操作返回失败、用户点击“重试恢复”。
- **流程**：关闭意图生效后停止新的功能请求；显示“正在恢复系统设置”；按对应模块既有快照 / 租约恢复并回读。成功显示关闭及恢复结果；失败显示“功能已关闭 · 系统设置恢复失败”，保留可用重试入口。恢复未完成时避免重复发起同一操作。
- **规则**：恢复只处理本功能实际持有的设置，遵循 SC1 的接管所有权检查和 KA1 的辅助程序恢复规则，不覆盖用户或其他工具后续改动。恢复失败不隐藏、删除恢复凭据，不显示“已恢复成功”。普通设置组禁用时，状态卡和重试按钮仍可操作。存在未解决的恢复错误时，重新开启先提示完成恢复，不直接创建相反的新接管 / 租约。截图与唤醒独立恢复，一个模块失败不自动修改另一个模块。
- **边界**：没有接管 / 合盖能力时正常关闭，不伪造失败。权限变化、辅助程序失联、其他工具冲突和部分恢复失败须分别说明；需要系统确认时仍由原确认流程处理，不以总开关获得新增权限。重试成功后保持关闭意图，不自动重新开启模块或旧手动计时。
- **数据**：用户启用意图、实际功能状态、是否拥有系统设置、待恢复字段 / 租约、恢复中 / 成功 / 失败、错误原因、最近回读结果与重试状态；不保存图片或任务正文。
- **验收**：分别模拟和实机核验普通成功、系统恢复失败、部分失败与重试成功。失败期间总开关关闭但错误与重试可见，其他设置仍置灰；回读成功后才显示恢复成功。外部已改动的设置不被旧快照覆盖，无所有权时不写系统设置。

## 5. 关键状态与入口矩阵

| 场景 | 总开关 | 下方设置 | 图标与菜单 | 实际效果 |
| --- | --- | --- | --- | --- |
| 挂绳正常开启 | 开 | 可操作，沿用分项选择 | 保留，显示已开启 | 按分项接收与展示 |
| 挂绳正常关闭 | 关 | 保留显示、置灰禁用 | 保留，可重新启用 | 不接收 / 不展开；图片保留 |
| 唤醒开启、没有任务 | 开 | 可操作 | 保留，显示等待 | 不凭开关开启就持续保持 |
| 唤醒开启、有效任务 | 开 | 可操作 | 保留，解释保持原因 | 按 KA1 保持与保护规则执行 |
| 唤醒主动关闭 | 关 | 保留显示、依赖控件禁用，分区可只读切换 | 保留，可重新启用 | 立即停止本功能保持请求并恢复，不取消外部任务 |
| 正在恢复系统设置 | 关，恢复期间防重复操作 | 保留显示、禁用 | 保留，显示正在恢复 | 等待真实回读，不先报成功 |
| 恢复失败 | 关 | 保留显示、禁用；重试入口可用 | 保留，明确失败 | 保存恢复义务，不假称系统已恢复 |
| 重新开启自动唤醒 | 开 | 恢复原偏好 | 同步开启 / 等待或保持 | 重新判断未结束任务及保护，不凭进程常驻保持 |
