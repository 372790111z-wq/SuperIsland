## 2. 目标与不可破坏的边界

用户开盖后能回答：这次有几个主聊天，它们各自有哪些子任务；哪个执行仍运行/等待/未知；哪一轮明确完成/失败/取消；实际保持是否释放、电脑是否睡过。

1. **聊天归属、当前执行、轮次结果、保持事实、睡眠事实分开。** 某轮 completed 不代表聊天永久结束；open 不代表正在运行。
2. 归并为只读展示投影，不合并真实执行身份，不生成任务终态，不清空 pending、不改变 KA1 保持、30 秒宽限或后台唤醒后再次请求休眠的守卫。
3. 保留用户已定政策：仅合盖且所有已监测执行真实终结、按原规则确认释放后才可请求睡眠；开盖不主动睡眠。请求受理不等于真实睡眠。
4. WorkBuddy 仍不监控；不增加来源、不重接 hooks、不改来源配置、信任、权限或系统电源设置。
5. 不读正文、工具内容、transcript、错误正文或凭据；不向其他聊天发消息、不停止/恢复/取消现有任务。
6. 本轮归属实证和元数据能力限 Codex；ZCode 等已有来源继续保留原有真实执行状态，缺可靠父子关系时单列，不冒称完成跨来源归并。

## 3. 层级、身份与展示

### 3.1 三层对象

| 层级 | 展示对象 | 身份与规则 |
| --- | --- | --- |
| 主聊天 | 一行“标题/匿名名称 + 来源 + 聚合执行状态” | 同来源/通道/已绑定本地 profile 内，通过可信父子链找到根；根仅作为分组容器时不额外生成真实任务 |
| 子任务 | 展开主聊天后就地显示子会话 | 保留真实会话身份，根自身执行另列“主聊天自身”；嵌套子任务都归根，详情保留直接父关系 |
| 轮次 | 子任务内再次展开 | 每个稳定 turn/task 身份独立，旧轮终态保留，新轮不会继承旧轮完成 |

同名不同 ID 不合并；不同来源/通道/profile 不跨边界合并。不能依据标题、时间接近、工具数或正文猜父子关系。重复 hook/notify/刷新按既有规范化身份去重；父子关系是层级，不是重复执行。

### 3.2 计数、编号与分类

- 标题栏改为“主聊天 N 个 · M 个子任务”，N 为已确认根容器数，M 为已纳入本周期的子会话数。一个会话多轮不增加主聊天或子任务数；“K 轮执行记录”只在详情显示。
- “主聊天自身”不是子任务；只有子记录参与周期时，允许根容器本身没有独立周期内执行。
- 主聊天状态分布若展示，使用第 4 节四种状态，总数必须等于 N；不再将轮次完成数标成“已完成聊天”。轮次失败/取消保留，不混进成功数。
- 归属待确认记录另列计数，不挤进 N/M。已知会话但不知其是否为根时，不能自行当主聊天。
- 保留原有可靠用户/后台/未分类边界。只有真实可确认的用户主聊天纳入用户汇总；类型未知但归属已知的记录可在“类型待确认”区按同样层级展示，并明确不计入用户任务汇总。父子关系或标题不用于猜分类。
- 根、子会话、轮次均按周期内首次纳入顺序稳定编号。显示标题缺失/空白/未授权/读取失败时用“主聊天 N”“子任务 N”；同名旁保留编号。
- 与实际保持相独立：可能显示“状态待确认”同时确认实际已释放，也可能执行已结束而仍在宽限内保持；分别解释，不篡改状态凑一致。

### 3.3 无法归属与容量

- 关系缺失、多父冲突、循环、自指、链过深、损坏或跨 profile 时，记录保持原身份，单列“归属待确认”；不随意选第一个父节点。
- 只处理已接入且有真实执行记录的目标及必要祖先，不能把整个会话数据库枚举成新的受监测任务。
- 沿用最多 1024 执行记录、48 时间线节点和 2 MiB 摘要上限。祖先与关系读取有独立节点/深度/耗时预算；达到预算标记不完整，不截掉活动成员后宣称全组结束。
- 容器无执行时不造 completed。清单为空表示无可用记录，不证明任务已结束或保持已释放。

## 4. 状态语义与证据规则

### 4.1 执行状态、关系状态与轮次结果

| 证据 | 可显示 | 不可推导 |
| --- | --- | --- |
| 真实运行事件，或可靠当前来源快照 active/inProgress | 当前执行运行中 | 仅进程存活、会话 open 或旧 active 缓存不能当新运行证据 |
| 真实等待确认/用户输入事件 | 等待确认 | 不作为完成或空闲 |
| 可靠当前会话 idle 且已知执行完整覆盖、最新相关轮次均明确终结 | 当前无执行；符合聚合条件时“本次执行已结束” | 不表示会话被永久关闭、整个长期目标完成或以后无新轮 |
| 某个精确 turn/task 的 completed/failed/interrupted + 有效结束时间 | 本轮已完成/本轮失败/本轮已取消 | 不能单凭此行宣告会话或主聊天整体结束 |
| thread_spawn_edges.status = open | 会话未关闭（关系说明） | 不是执行运行状态；closed 同样不自动等于成功 |
| 缺失、读取失败、旧快照、枚举不完整、未知值 | 状态待确认 | 不按失联、超时、Stop、重启或来源断开判终态 |

“当前无执行”需要可靠会话运行状态，不可由最近一轮 completed 自动补出。已有来源不提供可靠会话级状态时，仍可显示精确轮次结果，当前会话/组状态保留待确认。不得为补齐界面启动其他聊天、读取消息或使用会携带消息摘要的接口。

### 4.2 主聊天聚合顺序

在同一快照时点，将主聊天自身与已纳入本周期的所有子会话一起评估：

1. 任一成员有有效运行证据：组显示“运行中”。其他未知/等待成员仍在详情明确显示，不被吞掉。
2. 没有已知运行、但任一成员有有效等待证据：组显示“等待确认”；同时保留未知成员提示。
3. 无上述证据，但存在未覆盖成员、未知/过期状态、冲突或未明确终结执行：组显示“状态待确认”。
4. 只有主聊天已可靠空闲、相关会话和轮次完整覆盖、每条已开始执行均有精确真实终态且不存在更新运行/等待/未知时，组显示“本次执行已结束”。无成员执行事实不凭空标结束。

若只监测到部分来源/部分会话，界面不得将“本次执行已结束”解释为该主聊天全部未监控工作结束。统计说明明确这是已接入且证据完整的本次执行集合，不是对会话长期目标的完成承诺。

### 4.3 顺序、重入与历史快照

- 同一身份复用既有事件顺序和精确 turn ID；旧轮迟到终态不能覆盖新轮的运行/等待。
- 同一子会话下一轮开始，当前周期内显示新状态，历史轮结果保持；不增加同一个子会话计数。
- 本次实际开盖是截止点。开盖后开始的新轮不改写本次快照；可信迟到事件只有能证明发生于本周期才按原 KA2 边界处理，不把读取时刻当事件时刻。
- 父子关系在快照内固定。开盖后才得知且缺少周期内有效性证据的关系，不倒改历史分组；之后周期可使用。
- 标题为标签，不参与状态/去重/电源决策。标题缺失的子任务可通过根标题和稳定子编号辨认，不编造子标题。
- 时间线使用“主聊天 N / 子任务 M / 第 K 轮 · 本轮已完成”等明确粒度；已有电源节点保持原义，不能把单轮结束写成“所有任务结束”。

## 5. 功能点（八维度）

### KA2-G01 · 按主聊天归并及展开

- **业务目的**：准确回答这些执行属于哪个主聊天，避免将同一父聊天的子任务当作多个独立聊天。
- **使用者**：查看最近合盖回顾的本机用户。
- **触发**：已有自动回顾或杯子菜单重看；沿用 `si.ka.recap.tasks`，组/子任务详情预留新原生标识。
- **流程**：读取本周期身份与可信父子关系 → 找根并归并 → 默认每个主聊天一行 → 展开根自身和子任务 → 展开轮次 → 收起/关闭/重看。
- **规则**：遵循第 3 节；就地展开，不新增页面、弹窗或来源接入。聚合保留真实身份与分类。
- **边界**：标题为空匿名回退；同名根分开；多父/循环/缺失单列；长列表内部滚动，关闭入口可达。重开同一周期保留稳定编号。
- **数据**：来源/profile 范围、既有匿名会话/轮次身份、父关系、根身份、可靠分类、周期内编号；标题仅内存标签。
- **验收**：三个同根子会话显示 1 个主聊天/3 个子任务，多轮不增子计数；不同根同标题仍分开；缺父不猜归属；关闭和重看不发任何任务或电源命令。

### KA2-G02 · 执行状态与轮次结果分层

- **业务目的**：避免单轮完成误报主聊天整体结束，以及 open 误报运行。
- **使用者**：需要判断仍有什么执行未结束的用户。
- **触发**：周期内真实任务事件/可靠元数据刷新，及开盖快照渲染；沿用 `si.ka.recap.summary` 和 `si.ka.recap.timeline`。
- **流程**：精确归属轮次结果 → 结合可靠当前会话执行状态 → 按第 4 节聚合组状态 → 分层呈现状态与证据时间。
- **规则**：组四类状态与轮次终态分别表述；运行优先于等待，未知不能终结；只读投影不生成 Engine.Event。主聊天自身 idle 不能覆盖活动/等待子任务。
- **边界**：新轮压过旧轮、缓存失效、未知字段/缺分页、失败/取消、未监控范围均明确处理。缺会话 idle 证据时不由轮次 completed 推导。
- **数据**：已接入源的真实状态与时序、精确 turn 终态、会话状态证据/质量、枚举完整性；不创建第二套任务执行状态机。
- **验收**：主运行/子完成仍运行；子新轮运行同时保留旧轮完成；只有 open+completed 但当前未知时待确认；主 idle+子等待仍等待；全部可靠空闲且各执行明确终结才显示本次结束；失败/取消不算成功。

### KA2-G03 · 最小元数据读取与隐私回退

- **业务目的**：在用户批准范围内取得可靠归属和可辨认名称，保持现有任务与隐私边界。
- **使用者**：明确同意新增本机元数据范围的用户；未授权用户仍可看匿名记录。
- **触发**：第 6 节新增授权已明确取得，已接入 Codex profile 存在目标执行；同意前不启用新增读取。
- **流程**：匹配已有目标 → 有界只读查必要父链/标题 → 内存中规范化/哈希 → 更新展示 → 开盖固定摘要；失败采用匿名/待确认回退。
- **规则**：数据库只读、query_only、逐列 authorizer、同 UID/普通文件/路径校验、离主线程及短预算；结果到达时重验来源/profile/代际/身份，旧异步结果不得串入新连接。
- **边界**：schema 不兼容、文件替换/权限失败/超时均保留未知；不扫描其他 profile、旧库、消息或凭据，也不自动扩列。撤回许可立即停读并清空内存标题，新摘要不再新增关系。
- **数据**：精确允许范围见第 6 节；标题不入回顾/验收文件/日志/通知/annotation，不上传；原始 ID 仅内存匹配，落盘为既有一致哈希与必要关系。
- **验收**：未授权/撤回后无新增查询；authorizer 拒绝非白名单；标题空/损坏/过长/控制字符被安全处理；写入摘要不含真实标题/原始 ID；任意读取失败不会改变 pending/保持和终态。

### KA2-G04 · 冻结摘要、兼容和独立电源事实

- **业务目的**：让新旧回顾可恢复，且分组/展开永远不干预当前执行或电源。
- **使用者**：开盖回看或重启后手动查看摘要的用户。
- **触发**：周期写入/开盖/重启只读恢复/关闭重看；沿用原 KA2 周期与最小留存机制。
- **流程**：周期内累计事实 → 开盖固定任务及分组 → 私密原子保存 → 手动重看；旧摘要缺父关系时显示归属待确认。
- **规则**：沿用当前+最近一个周期、容量与质量边界；新版本可读旧摘要但不补造父子或整体状态。标题不持久化，重启后可匿名回退，不能用当前执行状态回写旧开盖快照。
- **边界**：容量、损坏、重启缺口、迁移失败均标记不完整并保留可恢复旧数据；不为展示修改 helper、lease、通知、pmset 或全局保持设置。
- **数据**：现有摘要增补可选匿名父/根关系及状态证据质量，不另建长期任务库；状态与电源时间分别保留。
- **验收**：旧 fixture 可读；开盖后新轮不变历史状态/计数；展开/重看不改变 pending、断言、睡眠请求次数；实际持有、释放等待、释放未确认、受理未睡分别正确展示。

## 6. 本次需明确确认的持续读取范围

### 6.1 新增范围（用户已明确授权，随修复版安装启用）

仅已连接 Codex 本机 profile，且仅已有受监测执行及其必要祖先：

| 数据位置 | 允许列/字段 | 用途 |
| --- | --- | --- |
| Codex 当前状态库 `state_5.sqlite` 的 `threads` | `id`、`title`、`attached_thread_parent_id` | 内存 ID 匹配、根/子归属及根标题标签 |
| 同库 `thread_spawn_edges` | `parent_thread_id`、`child_thread_id`、`status` | 必要父链与关系验证；status 不当运行状态 |

不读取该库其他列/表，不依赖诊断时的旧目录库。路径来自已绑定 profile，不硬编码用户/PID；schema 不匹配则回退，不自动扩展到其他库。查询虽可为哈希匹配在库内部遍历 ID，只有目标及必要祖先可投影标题/关系到 App，不返回无关会话元数据。

- 标题仅驻内存并在必要展示时使用，长度/控制字符受限、作为纯文本；不进入持久回顾、日志、通知、导出或上传。
- 原始会话/轮次 ID 只内存匹配，持久化保持现有哈希约定；明确区分 Engine 已哈希 ID 与 recorder 二次哈希，避免匹配错误。
- 父链用于呈现，不把未监测祖先/兄弟会话自动纳入保持或生成虚假运行记录。

### 6.2 继续沿用的范围及运行证据

- `thread_history_1.sqlite.thread_turns` 仍仅 `thread_id`、`turn_id`、`status`、`started_at`、`completed_at` 五列；限已接入匹配执行，允许为这些会话核对最近轮次，不能用旧轮代表最新轮。
