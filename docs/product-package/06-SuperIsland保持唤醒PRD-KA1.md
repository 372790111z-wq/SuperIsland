## 1. 目标与范围

本机有任务正在执行时，根据明确的任务状态或用户的手动计时保持 Mac 工作；已开始任务在等待用户、空闲观察或信号中断时仍持续保持；只有全部已开始任务明确完成、取消或失败后，延迟 30 秒释放。低电量、过热、手动停止与显式断开仍优先。用户通过现有 SuperIsland 菜单栏快速操作，在设置窗口独立页面管理来源、屏幕策略、合盖权限与恢复状态。

首版包括普通防空闲休眠、自动与手动模式、原 17 个来源或独立接入形式及新增 5 款本机工具（CLI / 桌面各自核验，共 27 项清单条目，其中 Kimi Code 两项暂缓，其余 25 项继续核验）、MacBook 单独授权的合盖运行、Mac mini 适配、三种屏幕策略、保护与异常恢复、可选完成提醒。既有音量、亮度、Mac 通知、截图挂绳、窗口管理必须保持正常。

本需求不新增独立菜单栏图标，不把应用打开当作任务忙碌，不读取用户任务正文。原型右侧设备切换、快进、情景按钮及模拟授权仅用于评审，不进入正式产品。合盖能力需独立实现和实机验证，不复制或调用 HoldMyLid 的签名绑定辅助程序。

## 5. 功能点

下列 `si.ka.*` 是预留稳定标识。原生实现时采用对应 accessibilityIdentifier；HTML 标注若适用再建立真实 `data-annotation-id`。当前不写入假 selector，不修改既有标注版本指针。

### KA1-F01 菜单快捷控制

- **业务目的**：无需打开设置即可查看原因、开始或停止保持。
- **使用者**：本机 SuperIsland 用户。
- **触发**：现有菜单栏菜单的「保持唤醒」，预留 `si.ka.menu`。
- **流程**：展开显示状态、原因、运行来源数与适用的合盖状态；选择自动或手动快捷时长；暂停、停止或打开管理页。
- **规则**：菜单与设置使用同一状态；开启自动时清除旧手动期限，手动快捷项明确切入手动模式；停止同时关闭总开关并执行释放。
- **边界**：无来源时自动模式显示等待接入；普通保持成功而合盖失败时分别反馈；设置窗口已经打开或关闭后再打开均可正确定位。
- **数据**：总开关、模式、有效保持、原因、期限、暂停期限、运行来源数、合盖就绪与恢复状态。
- **验收**：菜单开启后设置同步；设置停止后菜单同步；再次打开管理页成功；无任务不会误显示运行，失败不显示成功。

### KA1-F02 独立管理页面与状态解释

- **业务目的**：集中管理策略和异常，解释为什么正在保持或没有保持。
- **使用者**：本机用户；无需管理员权限即可查看普通状态。
- **触发**：设置侧栏或菜单管理入口，预留 `si.ka.settings`、`si.ka.status`、`si.ka.master`。
- **流程**：进入运行策略页；查看状态卡、电源、来源数、合盖支持；切换任务来源和保护与恢复；修改偏好即时重新判断。
- **规则**：请求开启与实际生效分别表示；状态卡展示最高优先级原因，其余问题在详细区域可见。已开始任务的 waiting 显示等待确认继续保持，idle 或陈旧信号显示状态待核实继续保持，不冒称仍在计算或已经完成。合盖未启用、等待授权、保护停止与辅助程序异常分别说明。
- **边界**：不在设置页面打开时才维持监测；窗口关闭不停止任务；来源空列表、权限拒绝、恢复冲突都有可操作反馈。
- **数据**：共享状态快照、偏好、能力、异常原因、最近变更时间；界面不另存一份业务状态。
- **验收**：菜单与各分区始终一致；收起或关闭设置后仍按策略运行；低电量与合盖失败同时发生时原因不互相掩盖。

### KA1-F03 自动任务聚合

- **业务目的**：让已开始的长任务在运行、等待或状态未知时持续保持，全部任务明确终结后再交还系统休眠策略。
- **使用者**：已主动接入并启用来源的用户。
- **触发**：自动模式开启后的有效任务事件，预留 `si.ka.mode`、`si.ka.sources`。
- **流程**：接收可信 running 事件，检查保护后建立未结束任务并取得保持；waiting、idle 或无新信号都保留该理由；全部已开始任务收到 completed / failed / cancelled 后开始 30 秒释放计时；新 running 取消释放并开始下一轮。
- **规则**：按来源与会话分别维护状态；一个会话结束不能释放另一未结束会话。首次 waiting / idle 不凭空激活；已开始后的等待、空闲及未知都不等于终结。45 秒信号陈旧只影响状态解释，不产生任务截止时间。重复终结事件不延长 30 秒；终结后的 PostToolUse 等续报不能重开原轮次，必须是更高序号、带明确新开始依据的 running。
- **边界**：重复、乱序、意外失联、显式断开、重连、进程退出与 App 重启分别处理。公开 Stop / AfterAgent 等事件可能先于最终决策或重试，不能直接当作可信完成；映射为待核实继续保持。不具备完整结束证据的来源不能声称可靠自动释放。显式断开撤销该来源的保持理由，其他未结束会话可继续保持。会话记录上限为 1024；容量已满又收到新 running 时，不静默漏掉防护，而是锁定该来源为未知并继续保持，提示核实后显式断开重接或手动停止；保护与停止仍优先。
- **数据**：来源 ID、匿名会话 ID、可选匿名 taskID 与 startsTask、连接代次、事件 ID/序号、接收时间、是否已真实开始、明确终结状态、连接健康、容量未知锁定与释放期限；taskID 和 startsTask 纳入 HMAC 认证，任务来源必须明确本地依赖。
- **验收**：两会话交错结束无误释放；等待、idle 与信号未知超过 24 小时仍保持；仅最后一个任务明确终结后 30 秒释放；重复终结不延期，新 running 取消释放；陈旧与重复序号不能停止新工作或重新激活已结束会话；同会话不同任务轮次隔离，终结后续报不重开；1024 容量溢出仍保持来源级未知，不能因未记录的新任务而放行休眠。

### KA1-F04 手动计时、暂停与停止

- **业务目的**：支持没有适配器的临时任务，并给用户明确结束控制。
- **使用者**：所有本机用户，不要求已接入任务来源。
- **触发**：运行策略的手动模式、开始、暂停、停止，预留 `si.ka.manual`、`si.ka.pause`、`si.ka.stop`。
- **流程**：选择时长并开始；暂停立即释放；提前结束暂停或到期后重新检查；手动期限到达后关闭总开关；停止取消当前运行与计时。
- **规则**：手动受所有保护条件约束；暂停不延长原手动期限。重复开始用新时长替换本次计时，不叠加多个保持。切到手动但未开始时不保持。
- **边界**：暂停期间手动期限已过则不恢复；休眠/唤醒后先校正期限再决定是否保持；修改系统时钟不应延长承诺时长；重启不续跑旧计时。
- **数据**：模式、会话开始时间、可信经过时间、手动到期、暂停到期及操作来源。
- **验收**：覆盖 30/60/120 分钟与不限时；到期释放；暂停期间无本功能保持；停止后旧任务事件不能绕过关闭状态。

### KA1-F05 来源接入、管理与断开

- **业务目的**：清楚接入全部约定来源，并保护用户原有配置。
- **使用者**：希望按任务自动保持的本机用户。
- **触发**：任务来源列表的搜索、接入、管理与断开，预留 `si.ka.source.<source-id>`。
- **流程**：读取版本及现有配置，说明将添加的接入项；用户主动接入后只合并本功能所需配置；回读并等待验证事件；断开时撤销本功能项并使旧会话失效。
- **规则**：「配置已写入」与「已验证接通」区分；不覆盖其他 hook、插件和用户配置。重试幂等，同一配置不重复追加；断开只清理本功能拥有的记录。适配器必须区分明确新开始与工具续报，不能用迟到的上轮终态结束新任务。
- **边界**：版本不兼容、配置格式错误、权限不足、配置被外部修改时停止该写入并提示；无法安全归属的项不自动删除。不静默安装第三方软件或依赖。WorkBuddy 公开 generation_id 与本功能拥有的 Pi UUID 经哈希形成匿名 taskID，隔离同一会话的任务轮次；没有可靠轮次身份的外部终态继续作为未知线索，不释放已开始任务。
- **数据**：适配器版本、目标版本、接入方式、配置归属、修改前必要快照、验证结果、最近事件时间、匿名任务轮次和明确开始标志；原始 generation_id / UUID 仅在适配器内处理，不上报原值，快照不收集无关私密内容。
- **验收**：原有自定义配置完整；重复接入无重复项；断开后旧 token/代次及事件不生效；27 个核验条目逐一提供真实事件证据或明确未完成的阻塞；补测同会话新旧轮次交错、迟到终态、终结后工具续报和缺轮次身份，实际来源端自动完成与释放仍待实测。

### KA1-F06 MacBook 合盖授权与运行

- **业务目的**：用户明确选择后，让本地任务在支持的 MacBook 合盖场景继续运行。
- **使用者**：具备机盖能力的 MacBook 用户；安装授权由 macOS 系统流程处理。
- **触发**：「设置合盖支持…」及启用/关闭，预留 `si.ka.helper`、`si.ka.lid`。
- **流程**：说明权限与恢复机制；调用系统授权；检查辅助程序身份、连接和能力；用户启用后，仅在有效保持期间续租；停止时请求释放并回读结果。
- **规则**：安装成功不等于合盖运行成功；普通唤醒和合盖就绪分别显示。未启用、等待授权、保护已停止及辅助程序异常均显示具体原因，不使用含混的「当前不保证」。用户从未授权时不得自动注册。辅助程序仅接受签名校验通过的本 App，提供有限操作，不开放任意命令执行接口。
- **边界**：授权取消/拒绝可继续普通模式；helper 不可用时立即提示合盖未就绪，不承诺继续运行；Mac mini 不显示授权入口。拒绝绕过系统安全限制来冒充成功。
- **数据**：授权状态、helper 版本/身份、启用意愿、租约 ID/到期、实际应用状态和失败原因；不得保存管理员密码。
- **验收**：真实授权取消、成功、断连与重新授权；合盖无外屏及有外屏任务连续性；租约停止后恢复读回；仅普通断言成功不能通过合盖验收。

### KA1-F07 屏幕策略

- **业务目的**：按使用场景选择屏幕显示，同时独立保持后台任务。
- **使用者**：MacBook 与桌面 Mac 用户。
- **触发**：「屏幕策略」选择框，预留 `si.ka.screen`。
- **流程**：跟随系统时只保持任务；常亮时取得本功能的显示保持；熄屏时在新的有效保持周期开始执行一次可支持的熄屏动作。用户唤醒屏幕后不循环强制熄屏。
- **规则**：策略仅在有效保持期间执行；关闭、暂停或保护触发时释放本功能显示保持。切换策略即时应用；屏幕关闭不等于锁屏，不能代替系统安全锁定。
- **边界**：MacBook 外接桌面场景保留外屏；若当前接口只能关闭全部显示器，则该场景的熄屏选项显示不可用及原因，不偷偷熄灭外屏。Mac mini 无内屏，按支持的连接显示器能力执行；无屏幕不报虚假失败。
- **数据**：策略、显示器能力及拓扑、当前保持周期、已执行动作、显示断言和不可用原因；不修改用户亮度偏好。
- **验收**：系统策略可正常自动熄屏且任务继续；常亮和停止释放分别验证；主动熄屏后输入可唤醒且不马上再熄屏；外屏保留用实机确认。

### KA1-F08 电源与热保护

- **业务目的**：避免低电量、断电或过热时持续保持。
- **使用者**：全体用户；电池相关控件仅适用有内置电池设备。
- **触发**：电源/电池/低电量模式/热压力变更与任何保持请求，预留 `si.ka.protection`。
- **流程**：每次状态变化优先评估；命中保护立即停止本功能保持与租约，显示原因；条件解除后由用户执行恢复检查。
- **规则**：电量低于阈值才触发，等于阈值可运行；仅接电和遵循低电量模式默认开启但可调整；严重/危急热压力保护不可关闭；保护优先于手动与自动。阈值仅接受 5—50 的整数。
- **边界**：MacBook 电源数据缺失时不假定安全，阻止新的保持并展示未知；Mac mini 缺少电池是正常能力差异。恢复检查必须重新检查所有条件，不能只清除文案。
- **数据**：电池能力、电量、电源、低电量模式、系统热压力、保护锁定原因和偏好；不以未经测量的摄氏温度描述热状态。
- **验收**：边界 19/20/21%、拔插电源、低电量模式与严重热压力；自动和手动都停止；条件仍不满足时不能恢复；桌面 Mac 不被虚假电池状态阻断。

### KA1-F09 异常恢复、撤销与冲突

- **业务目的**：退出、崩溃、升级或断连后不遗留本功能造成的持续防休眠设置。
- **使用者**：用户及有限权限的本机恢复组件。
- **触发**：停止、正常退出、主进程异常、租约到期、系统重启、授权撤销，预留 `si.ka.recovery`。
- **流程**：操作前记录必要基线与归属；正常结束释放并读取实际结果；主进程失联由 helper 的独立租约释放；重启后先检查未结事务；撤销时先恢复确认，再移除本功能 helper。
- **规则**：单次租约最长 180 秒，健康主 App 在保持有效时每 30 秒持续续租；可跨数小时或数天，不以租约时长限制任务。主 App 异常停止续租后按独立故障期限恢复，续期不能成为无人管理的永久开关；只释放本功能拥有的断言。任何全局电源值必须对比原值、最后写入值和当前值，不能盲目写回默认值；恢复失败显著展示待处理。
- **边界**：用户或其他电源软件中途改值则保留冲突现场，不覆盖其意图。helper 自身崩溃与系统重启不能只靠主 App 补救，必须验证独立恢复路径；无法证明有限恢复时不得启用该合盖方案。
- **数据**：最小恢复日志、事务 ID、基线、拥有者、最后写入值、租约期限、当前值、恢复结果；避免无关系统设置和私人内容。
- **验收**：正常退出、强制结束主 App、强制结束 helper、重启、撤销及第三方改值逐项验证；读回系统实际状态；失败时绝不显示「已恢复」，重启后总开关关闭。

### KA1-F10 完成提醒与隐私

- **业务目的**：提醒用户明确完成的任务，同时避免任务内容泄漏。
- **使用者**：启用提醒且授予 macOS 通知权限的用户。
- **触发**：已验证会话从运行转为明确完成，预留 `si.ka.notify`。
- **流程**：按授权状态说明并由用户触发系统授权；完成后发来源与状态通知；未授权不影响保持功能。
- **规则**：仅在有可信最终完成与对应任务轮次时通知一次；等待、失联、空闲、Stop / AfterAgent 或缺可靠轮次身份的外部终态都不称完成。匿名 taskID 和 startsTask 与状态一起纳入 HMAC 认证，字段篡改不得通过校验。事件不收集 prompt、任务正文、代码、聊天记录、工作目录和文件内容；日志亦遵守此规则。
- **边界**：系统专注模式或权限拒绝不承诺横幅可见；与现有 Mac 通知桥接协调，避免自身通知反馈循环或重复入岛。不强制改变系统通知设置。
- **数据**：提醒偏好、系统授权状态、来源名称、匿名会话/任务轮次去重标识、明确新开始标志、完成状态；事件通信只保留必要状态元数据并校验来源，不发送原始轮次标识。
- **验收**：收到一次明确完成仅提醒一次；重复事件不重复提醒；未知、等待和无轮次身份的终态不发完成；taskID / startsTask 篡改与重放被拒绝；使用含敏感测试正文的任务检查传输与日志均不含正文。各实际来源端的自动完成仍须独立实测。

## 6. 状态与事件契约

### 6.1 优先级与运行结果

1. 总开关关闭或停止：不取得新保持，执行尚未完成的释放；恢复冲突仍在页面保留。
2. 恢复冲突、保护条件或保护锁定：禁止开始，展示具体原因。
3. 暂停有效：不保持，显示剩余暂停时间。
4. 手动模式：仅已开始且未到期时产生保持意愿。
5. 自动模式：已真实开始且未明确终结的会话，或明确终结后的 30 秒释放期，构成保持意愿；waiting、idle、信号未知不结束已开始任务，未开始的这些事件也不建立保持。
6. 执行普通保持，再分别反馈合盖、屏幕策略结果。执行失败不能等同于保持成功。

任务状态与连接健康是不同维度：任务为 running / waiting / idle / completed / failed / cancelled；连接为 healthy / stale / disconnected。意外失联只标为未知，持续保留已开始任务，不伪造 completed；用户显式断开则立即撤销该来源理由。Stop / AfterAgent 等未经证实的终结线索显示为待核实保持。只有可信 completed / failed / cancelled 终结本轮；失败、取消与正常完成分别显示。

### 6.2 最小事件与防重复

每个适配器须明确版本、来源、匿名会话 ID、连接代次、事件唯一标识或单调序号、状态及本地执行依赖；接收端记录可信接收时间。心跳、进程存活和事件缺失的判断周期在适配器协议中写明并测试，不能把安静但仍在运行的任务直接视为完成。

本机接入需校验发送来源与会话凭据；如采用本地 HTTP，只绑定 loopback 并鉴权，不能接受网页或其他任意本机进程伪造事件。用户显式断开使旧凭据失效并撤销该来源会话；时序不明的事件进入待核验状态，不复活已终结会话。相同或较低序号不更新状态；更高序号的重复终结仅更新去重记录，不推迟原释放时间；终结后的 waiting / idle 不能复活，PostToolUse 等 running 续报也不能重开；只有明确新开始的 running 才能开始下一轮。重复上报相同任务时按稳定映射合并，不把 Cursor/Cursor Agent 等重复计数。

事件中的 taskID 与 startsTask 为可选兼容字段；存在任一字段时，两项取值与缺省情况均纳入同一 HMAC 认证，不能添加、移除或改写元数据后沿用原认证。原始来源轮次标识先哈希再离开适配器；WorkBuddy 采用公开 generation_id，本功能拥有的 Pi 扩展采用其 UUID。缺少可靠轮次身份时，外部结束线索不升级为可信最终状态，继续未知保持。所有实际来源端自动完成的正确性仍待实测。

任务记录容量达到 1024 后，新 running 若无法入表，建立有界的来源级未知锁定，不用丢弃事件来推导全部任务结束。该锁定持续保持并提示核实、显式断开重接或手动停止；显式断开清除该来源的记录及锁定，手动停止优先撤回本次保持，不冒称任务已完成。

### 6.3 持久化

持久化策略偏好、来源接入元数据和必要恢复事务。活跃任务、手动运行期限、暂停与有效保持不能凭历史缓存恢复为运行。App 启动先处理未结恢复，再等待用户重新开启与新有效事件。恢复记录不等于任务历史，不保存私人正文。
