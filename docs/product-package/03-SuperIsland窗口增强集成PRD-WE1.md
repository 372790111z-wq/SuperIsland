## 功能点 1：窗口增强设置与持久化

### 1. 业务目的

在 SuperIsland 现有设置窗口中提供统一、可理解的窗口增强配置入口，让用户能分别控制功能开关、快捷键、布局和高级行为。

### 2. 使用者

使用 macOS、允许 SuperIsland 管理窗口，并希望通过拖动、Dock、快捷键或调度中心提升窗口操作效率的用户。

### 3. 触发

用户打开 SuperIsland 设置并选择“窗口增强”。

### 4. 流程

1. 设置侧栏新增“窗口增强”，保留通用、模块、外观、扩展、高级和退出。
2. 用户分别启用核心能力、调度中心能力和快捷功能。
3. 用户为每个动作或布局录入快捷键。
4. 用户打开“高级…”设置调度空间、窗口间距、强调色和排除 App。
5. 设置变更立即写入本地持久化，并在下次启动恢复。
6. 鼠标移入或键盘聚焦核心功能、调度中心、快捷功能和布局时，左侧演示区即时切换对应效果。

### 5. 规则

- 总开关关闭时，所有窗口增强监听和快捷键停止响应，但保留子项配置。
- 子开关只影响对应能力，不得联动修改其他功能。
- 快捷键录入与功能开关独立；录入快捷键不得自动启用功能。
- 快捷键冲突时不得静默覆盖，必须显示冲突并保留旧值。
- 设置页面使用 SuperIsland 现有深色组件与尺寸，不嵌入 macOS 系统设置。
- Aero Shake、隐藏/显示所有窗口和隐藏其他窗口只出现在设置项、悬停演示与真实快捷操作中，不提供自创的中央“窗口动作”选择面板。

### 6. 边界

- 辅助功能未授权时允许浏览和编辑设置，但执行窗口操作时明确提示授权。
- 屏幕录制仅用于窗口缩略图；拒绝后降级为窗口标题，不影响基础布局与移动。
- 排除 App 后，该 App 不响应窗口快捷键、分屏和预览。

### 7. 数据

- 使用 `UserDefaults` / `@AppStorage` 持久化总开关、子开关、快捷键、布局快捷键、高级设置和排除 App bundle id。
- 不保存窗口内容、缩略图或用户文档。

### 8. 验收

- [ ] 设置侧栏存在“窗口增强”，外壳与现有设置一致。
- [ ] 所有开关、快捷键和高级项可修改并在重启后恢复。
- [ ] 高级页不出现授权、试用、购买或激活。
- [ ] 原有 15 个窗口功能/快捷功能入口均有对应的移入或键盘聚焦演示，移出后回到总览；新增文件快捷删除行说明支持范围，不在设置页执行真实文件演示。
- [ ] 权限缺失时不伪装执行成功。

## 功能点 2：窗口布局与快捷操作

### 1. 业务目的

让用户通过快捷键或拖动快速完成常用窗口布局、跨屏移动、居中和隐藏操作。

### 2. 使用者

频繁整理多个应用窗口或使用多显示器的用户。

### 3. 触发

用户触发已配置快捷键、拖动窗口进入边缘热区，或在悬浮分屏岛先选择分屏方案、再命中方案内的目标区域。

### 4. 流程

1. 系统读取当前前台 App 的可操作窗口。
2. 排除不可操作、全屏、系统层级或被用户排除的 App。
3. 根据目标屏幕的可用区域计算窗口 frame。
4. 执行移动和缩放，并给出成功或失败反馈。

### 5. 规则

- 设置页按 WINS 提供 10 个单窗口快捷键位置：左半屏、右半屏、最大化、左/中/右三分之一、上半屏、下半屏、左侧三分之二和右侧三分之二；每个位置可独立设置快捷键。
- 悬浮分屏岛只显示 4 个组合方案：左右二分、上下二分、左主右双、四宫格。方案是一级选择，方案内部区域是二级命中；不得把四宫格拆成四个一级按钮，其他方案同理。
- 四个四分之一区域是组合方案的内部目标，不在设置页重复生成四张快捷键卡。
- 窗口快捷功能包括 Dock 锁定屏幕、隐藏/显示所有窗口、隐藏其他窗口、移动到下个显示器、移动到上个显示器、窗口居中；同一区域另增独立的“快捷删除文件”，它不属于窗口动作枚举。
- 不支持缩放的窗口不得强制写入错误尺寸；移动可行时只移动并提示限制。
- 多显示器按系统排列顺序循环，断开显示器后重新计算目标。

### 6. 边界

- 没有可操作窗口时显示“没有可管理的窗口”，不执行空操作。
- 系统窗口、桌面元素、菜单栏、Dock 与 SuperIsland 自身窗口默认排除。
- 窗口最小尺寸、应用约束和屏幕安全区优先于目标布局。

### 7. 数据

- 输入：前台应用、AX 窗口、当前显示器、目标布局和用户设置。
- 输出：窗口位置与尺寸变更；不上传任何数据。

### 8. 验收

- [ ] 设置页只显示 10 个快捷键位置，不出现四张独立四分之一快捷键卡。
- [ ] 分屏岛只显示 4 个组合方案；在每个方案内部移动指针可分别选中其子区域，四宫格的四个区域落在正确象限。
- [ ] 6 项快捷功能只影响目标窗口或目标窗口集合。
- [ ] 不可缩放、无窗口、权限缺失和屏幕断开均有明确反馈。
- [ ] 排除 App 不响应上述操作。

## 功能点 3：窗口切换、Dock 与调度中心增强

### 1. 业务目的

把应用级切换继续细化到窗口级，并在 Dock 与窗口鸟瞰场景中提供可预测的预览、关闭、退出和反转操作。

### 2. 使用者

同时打开多个应用和多个窗口、需要快速定位具体窗口的用户。

### 3. 触发

用户使用 Cmd-Tab Plus、移入 Dock 图标、再次点击当前 App 的 Dock 图标，或进入 SuperIsland 的调度中心增强界面。

### 4. 流程

1. 读取运行中的普通应用与其可见窗口。
2. 有屏幕录制权限时显示本地缩略图；否则显示应用图标、窗口标题和数量。
3. 用户选择窗口后激活并前置。
4. 关闭窗口仅关闭选中窗口；退出程序必须二次确认并退出整个 App。

### 5. 规则

- Dock 窗口预览锚定对应 Dock 图标，不显示与该 App 无关的窗口。
- Dock 有屏幕录制权限时显示真实窗口缩略图，卡片为“App 名称—缩略图—窗口标题”结构；单窗口保持紧凑，多窗口横向排列。
- Dock 反转只在再次点击当前前台 App 时触发，不改变其他 App。
- 关闭窗口与退出程序必须是两个不同动作和快捷键。
- Cmd-Tab Plus 使用接近屏幕宽度的底部毛玻璃图标带；选中图标放大，具体窗口缩略图浮在该图标正上方，并随选择移动。

2026-09-11 用户确认的双微信规则：

- Dock 保持按安装路径隔离：主微信只显示主微信窗口，双开微信只显示双开微信窗口。
- Cmd-Tab 选到任意一个微信图标时，在现有窗口预览中展示两套已知微信安装的窗口；每张卡片标注“主微信”或“双开微信”，不新增实例选择步骤。共享是展示规则，不声称识别出了原生同名图标的唯一进程。
- 仅明确选择具体窗口后，才按该卡片真实进程和窗口身份激活或关闭。未选窗时松开 Command 维持系统原生切换；不得把共享列表首卡作为默认关闭或退出目标。切换图标、窗口关闭或失效时清理旧选择。
- 仅覆盖已确认的主微信与 WeChat-Work2 安装；其他同名应用、未知安装或强身份冲突不自动合并。原生切换器状态无法确认时，不执行延迟跨应用激活。
- 无操作对象的备用预览按各自安装展示并标为“应用预览”，不可激活或关闭；不把截图表面数量当成真实窗口数量。主微信透明截图问题仍单独保留。

### 6. 边界

- 受保护 App、无窗口 App、最小化窗口和跨空间窗口分别保留真实状态。
- 未保存内容是否可恢复由目标 App 决定；SuperIsland 不宣称可恢复。
- 系统不允许的 Mission Control 深度控制需以原生 PoC 结果为准，不用私有 API伪造完成。

### 7. 数据

- 只在本机短暂读取应用、窗口标题、frame、状态和可选缩略图。
- 不持久化缩略图，不上传窗口信息。

### 8. 验收

- [ ] Dock 单窗口、多窗口和标题降级态均可用。
- [ ] Cmd-Tab Plus 能选择具体窗口并正确激活。
- [ ] 两个微信 Cmd-Tab 入口均展示两套窗口且归属正确，Dock 仍分别展示。
- [ ] 从任一微信入口选另一套窗口后，松 Command 或点击均提交该真实窗口；无明确选择不改变原生行为，不误关共享首卡。
- [ ] 快速切图标、Esc、新一轮 Cmd-Tab、窗口退出或新鼠标点击后，不出现迟到激活或旧选择转移。
- [ ] 关闭窗口不会退出整个 App；退出程序有二次确认。
- [ ] 无法覆盖的系统级能力明确标记为受限或 PoC 未通过。

## 功能点 4：高级选项与权限边界

### 1. 业务目的

允许用户控制窗口布局细节并排除不应被管理的 App，同时清晰解释权限用途。

### 2. 使用者

需要定制台前调度、窗口间距、强调色或应用排除规则的用户。

### 3. 触发

用户在窗口增强设置页点击“高级…”。

### 4. 流程

1. 用户设置“预留台前调度空间”和“分屏窗口间距”。
2. 用户选择强调色。
3. 用户通过系统应用选择器添加或移除排除 App。
4. 用户查看当前 SuperIsland 版本或检查更新，点击“完成”返回。

### 5. 规则

- 强调色只改变窗口增强的热区、布局岛和选中反馈，不改变整个 App 主题。
- 排除 App 使用 bundle id 作为稳定标识，并显示真实 App 图标和名称。
- 本页不包含授权、试用、购买、激活或支付入口。

### 6. 边界

- 已卸载 App 仍可保留 bundle id，但显示“应用不可用”并允许移除。
- 系统应用选择器取消时不写入任何数据。

### 7. 数据

- 持久化台前调度、间距、强调色标识和排除 App bundle id 列表。

### 8. 验收

- [ ] 高级项修改后立即生效并持久化。
- [ ] 排除 App 可添加和移除。
- [ ] 页面不存在商业化授权入口。
- [ ] “完成”返回窗口增强主设置页。

## 功能点 5：Finder／桌面文件快捷删除（2026-09-17 增补）

### 1. 业务目的

让用户用自定义快捷键，将 Finder 或桌面选中的文件移到废纸篓，并保留系统的恢复途径。

### 2. 使用者

使用 Finder 或桌面管理文件，且已授予 SuperIsland 辅助功能权限的用户。

### 3. 触发

在“设置 → 窗口增强 → 快捷功能”设置“快捷删除文件”的组合键并单独开启功能；Finder／桌面处于前台且有文件选区时按该组合键。

设置入口标识：`data-annotation-id=window-enhancement-file-trash`。本项目使用 SwiftUI 辅助功能标识承载该映射，不新增网页业务入口。

### 4. 流程

1. 首次使用默认关闭、没有预设快捷键。用户录入、修改或清除快捷键不会改变开关。
2. 录入沿用现有至少一个修饰键、Esc 取消、单按 Delete 清除和可见清除按钮；与其他已配置功能冲突时保留原绑定并提示冲突。
3. 执行前复核窗口增强总开关、文件功能开关、绑定、辅助功能权限、Finder 前台状态及排除列表。
4. 排除名称编辑、其他文本输入、模态对话框或无法确定安全文件选区的情形。
5. 调用 Finder 自身明确且已启用的“移到废纸篓”菜单命令。其他应用前台、无选择或命令不可用时不执行，并反馈原因。
6. 菜单命令请求成功与文件实际移动分开：未观测到结果时只反馈已请求 Finder 执行，不虚报删除数量或完成状态。恢复通过 Finder／废纸篓的原生能力完成。

### 5. 规则

- 文件动作使用独立 ID `file.moveToTrash`，不加入 `WindowQuickAction`，不绑定当前前台窗口的关闭操作。
- 与现有功能共用快捷键存储、内部冲突校验、注册预检、清除及注册失败回退；本项只在 Finder 场景生效，不显示“覆盖其他 App 原生快捷键”的笼统警告。
- 总开关或本项开关关闭时停止执行但保留绑定；Finder 被排除时不执行。
- 仅在 Finder 前台且功能可用时注册文件快捷键；切走立即注销，回到 Finder 后按最新配置重新注册，其他应用保留该组合键的原行为。
- 一次物理按下最多执行一次；按住产生的重复事件不重复删除，确认按键释放后才允许下一次触发。
- 按键周期、Finder 前台会话或绑定变化后，旧周期排队的迟到回调失效；睡眠、会话退出、停止功能时取消旧操作。按键尚未释放时切回 Finder，不自动补做删除。
- 一次处理 Finder 当前选区，遵守系统菜单对文件、目录、位置与权限的限制。
- 只请求移到废纸篓，不调用永久删除或清空废纸篓，不自动确认任何永久删除弹窗。

### 6. 边界

- 仅支持 Finder 和由 Finder 管理的桌面，不扩展到第三方文件管理器、网页文件或应用内部附件。
- 正在重命名、文本输入或对话框无法排除时不执行；不模拟裸 Delete、不猜坐标，不读取私有文件数据补猜选区。
- 只使用已有辅助功能权限；不新增 AppleEvents／自动化授权界面、屏幕录制要求、网络访问或额外依赖。
- 受权限、卷类型或 Finder 状态影响无法移到废纸篓时，保留原文件并交由系统原生界面处理；SuperIsland 不代替用户接受不可恢复删除。

### 7. 数据

- `windowEnhancement.fileTrash` 持久化独立开关，默认 `false`；`windowEnhancement.shortcuts["file.moveToTrash"]` 存储组合键，默认缺省。
- `fileTrashEnabled` 进入既有 `configurationChanges`，运行时反馈不进入该配置流，避免反馈引起快捷键与窗口监听重建。
- 不保存选区路径、文件内容、删除历史或文件名日志；HTML 文件、废纸篓与撤销均为虚构数据，不代表 App 增加独立文件管理或撤销界面。

### 8. 验收

- [ ] 设置入口、录入、清除、冲突提示、默认值及重启持久化正确；开关与绑定独立。
- [ ] Finder／桌面选中的可丢弃测试文件移到废纸篓，未选择的文件保留，可用系统能力恢复。
- [ ] 其他应用前台、没有文件选择、正在重命名、文本输入、模态对话框、Finder 被排除、总开关关闭时不执行。
- [ ] 长按组合键只请求一次删除；释放后可再次触发；切走／切回 Finder、更新配置或恢复会话后，不执行旧按键周期的迟到回调。
- [ ] 没有权限或找不到明确菜单动作时反馈失败，不模拟按键或点击补救，不确认永久删除。
- [ ] 未安装、未实测阶段不得勾选原生行为通过；测试只在用户允许屏幕和鼠标操作后开展。

## 功能点 6：隐藏/显示所有窗口（2026-09-17 增补）

### 1. 业务目的

用同一个快捷键临时腾出桌面，再恢复刚才收起的一批窗口，保留用户原先最小化的状态。

### 2. 使用者

需要临时查看桌面或收起多个应用窗口的用户。

### 3. 触发

用户按已绑定的 `action.hideAll` 快捷键；设置项名称由“隐藏所有窗口”改为“隐藏/显示所有窗口”。

标注映射复用窗口增强设置入口 `data-annotation-id=window-enhancement-settings`；不为标注增加独立业务入口。

### 4. 流程

1. 初次触发按既有可管理窗口规则收起当前窗口，并记住本次成功收起的窗口身份。
2. 第二次触发恢复本次记住且仍存在、仍可操作的窗口；全部恢复或确认窗口已不存在后结束会话，暂时恢复失败的窗口保留待下一次重试。
3. 原先已最小化的窗口保持不变；后续继续按键时重新开始下一轮收起／恢复。

### 5. 规则

- 采用已确认的“仅恢复本次收起”范围，不提供“恢复全部已最小化窗口”的业务设置。
- 保留 `hideAll` 枚举值、`action.hideAll` 快捷键 ID、已有用户绑定及开关，不另建重复动作或迁移成新 ID。
- 沿用已有收起会话与窗口身份记录，不用全局“显示所有应用”替代精确恢复；不改动已验收的 Cmd-Tab、Dock、调度中心和全屏移屏策略。
- 设置说明明确“第一次收起全部，第二次恢复刚才收起的窗口”。
- `action.hideAll` 一次按下只切换一次，长按不反复收起／恢复；以 Carbon 按键释放事件解除本次按下限制，其他窗口布局和快捷键保留原有重复响应行为。
- 继续与“隐藏其他窗口”及 Aero Shake 共用一批可恢复会话：已有会话时，任一收起入口先恢复同一批，不叠加新的收起批次。

### 6. 边界

- 仍服从原有可管理窗口、应用排除、系统窗口及权限限制；不能操作的窗口不宣称已收起。
- 原先最小化、未参与本次收起、之后新建的窗口不加入恢复集合；已关闭或身份失效的窗口不重新打开。
- “打开全部”只表示恢复本次现有窗口，不启动应用、不创建窗口，不把原先最小化的窗口一起展开。
- 临时 AX 拒绝恢复时保留该窗口的会话所有权，下一次触发或停止清理可重试；短暂枚举缺失不直接丢弃，按既有多次观察规则确认失效。成功恢复、已被用户恢复或确认应用退出的窗口从待恢复集合移出。

### 7. 数据

- 继续使用 `action.hideAll` 的既有持久化快捷键及动作开关；本次会话只保留运行期的窗口身份，不持久化窗口内容或截图。
- HTML 中“全部已最小化窗口”仅保留为未采用的方案对比，不代表正式可配置选项。
