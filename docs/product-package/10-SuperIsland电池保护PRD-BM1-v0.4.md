## 2. 目标与范围

用户只需决定：是否保护电池、充到多少、是否主动放电。不再维护复杂的模式、日程和附加硬件设置。

| 保留 | 行为 |
| --- | --- |
| 电池保护 | 一个明确开关；用户关闭后持久保持关闭 |
| 可调充电上限 | 默认 80%，范围 80–100%，整数百分比；调整后点“应用”，关闭保护时点“保存” |
| 主动放电 | 接电且开启保护时，指定低于当前电量的目标，随时可停止 |
| 睡眠保护 | 保护开启时默认继续遵守上限；没有独立开关，不阻止系统睡眠 |
| 必要显示 | 当前电量、电源连接状态、实际充电状态、已保存上限、操作和恢复结果 |
| 必要安全机制 | 权限、能力和冲突检查；请求串行化、失败回读、自有变更恢复；不做成高级功能区 |

### 明确移除

- 校准、航海模式、自动放电、定时任务及充电控制捷径。
- 独立“临时充满”和“暂停充电”模式；达到充电上限后显示“已暂停充电”是状态，不是保留暂停按钮。
- 阻止睡眠、关闭显示器、合盖锁屏、退出后继续停充等可配置行为。
- 手动能源模式、MagSafe 灯色、复杂仪表、趋势分区和多分区显示定制。
- 用户可配置的过热控制模式；设备原生温度保护、控制过程中的必要安全检查不得删除或绕过。
- “允许充电至低于 80%”开关。本版限充统一 80–100%，主动放电目标独立，不能借此突破限充范围。

移除是入口、调度和执行路径一起停用，不是仅隐藏按钮。旧数据归档保留，不继续自动执行；正常电量读取及其他模块功能不受影响。

## 3. 页面与交互

### 3.1 灵动岛

沿用现有电池入口、展开/收起与模块导航。电池完全展开后只展示一页：电量和状态 → 保护开关 → 充电上限 → 主动放电 → 电池设置入口。不再有概览/充电/趋势分区。

完全展开面板按内容调整至可操作尺寸，保留现有刘海、肩部/内嵌顶栏和屏幕边界处理；不强塞入旧八分区布局，也不把 HTML 桌面背景、模拟工具和评审说明带入产品。紧凑入口保留现有电量提示。

### 3.2 设置窗口

“电池设置”进入现有 SuperIsland 设置窗口的“电池保护”页，不创建第二套设置窗口。设置页与灵动岛展示同一组控制、同一状态。统一齿轮仍执行通用设置路由。

### 3.3 短操作弹窗

主动放电使用目标确认弹窗；关闭保护使用恢复确认弹窗。均支持取消、Escape 和合理焦点返回。设置窗口关闭不会隐式应用尚未提交的上限，也不会终止正在执行的已确认放电。

## 4. 共用规则与状态

- **意图、保存值、硬件结果分开**：开启请求不是已保护，保存上限不是确认停充，恢复请求不是已解除限制。
- **状态可见**：请求中、限充生效、充电中、主动放电、系统管理、未授权、不支持、读数未知、恢复中、恢复失败均使用简明中文，不向用户展示协议号或底层错误码。
- **只恢复自身变更**：不得覆盖用户或其他工具后续更改；发生控制冲突时停止新的写入，提供原因及可行的恢复入口。
- **单一执行顺序**：多入口共用状态；重复操作、晚到回调、睡眠/拔电和退出不能重新激活旧模式。
- **能力按实际检查**：不绑定第三方应用版本；不支持的操作说明原因，不能伪造成功。目标设备上支持主动放电和睡眠限充的验证是核心交付门槛。
- **用户关闭持久化**：立即保存关闭意图；恢复失败也不在重启后重新开启保护。未完成的恢复义务单独持久保存，启动后只恢复，不借恢复重新启用。
- **上限含 100%**：用户明确选择 100% 即允许充满；睡眠遵守用户设置，不另设隐藏的 80% 限制。默认 80% 用于避免默认充满。
- **不强制自动降电量**：当前 86%、上限 80% 时执行限充，不自动主动放电；主动放电必须由用户明确发起。

## 5. 功能点

新功能使用 `BM1-Sxx`，避免将历史 `BM1-Fxx` 的不同语义混为一谈。下列标识对应本轮实现映射；系统行为没有独立 UI 节点，设备效果另行验收。

### BM1-S01 · 单页入口与基本状态

- **业务目的**：快速看懂电池状态并找到三个常用操作。
- **使用者**：SuperIsland 本机用户；无内置电池设备显示不可用说明。
- **触发**：现有电池入口与“电池设置”；预留 `si.bm.simple.panel`、`si.bm.simple.settings-entry`、`si.bm.simple.status`。
- **流程**：展开电池页 → 查看状态/操作 → 打开设置 → 关闭设置返回原上下文；入口之间共享有效上限、草稿及操作进度。
- **规则**：一个电池控制真源；没有旧分区和高级入口。未提交草稿不当作有效上限显示，当前状态必须对应真实读数和执行反馈。
- **边界**：读数缺失显示“— / 暂时无法读取”，不显示 0%；无电池或能力不足不得仍显示保护成功。设置重复打开复用现有窗口；操作文本不被截断。
- **数据**：电量、接电状态、充电状态、采样有效性、保护意图、有效上限、草稿、运行模式、恢复状态。
- **验收**：岛内应用 82% 后设置窗口显示相同值；打开/关闭设置不重复实例；未知读数无假数字；键盘、VoiceOver、窄窗口和刘海布局可操作。

### BM1-S02 · 保护开关与持久关闭

- **业务目的**：用户能够明确控制本功能是否运行，并安全交回系统管理。
- **使用者**：具有本机辅助程序授权或可由本人完成授权的用户。
- **触发**：保护开关；预留 `si.bm.simple.enabled`、`si.bm.simple.restore`。
- **流程**：开启时检查权限/能力/冲突 → 发送限充请求 → 回读并显示结果；关闭时确认 → 保存关闭意图 → 停止主动放电并恢复自有控制 → 确认后显示系统管理。
- **规则**：默认上限 80%；新配置在手动开启前不写硬件。关闭后重新打开 App 或重启设备仍关闭；保护原本开启且恢复条件允许时可继续按已保存上限运行，但不自动继续临时放电。关闭确认取消不改变当前意图或模式。
- **边界**：未授权需本人完成系统授权，不自动绕过；恢复失败显示“等待确认恢复”，不能显示已完成关闭。关闭意图仍保存为关闭，残留恢复义务不会被删除。
- **数据**：持久保护意图、上限、权限/能力、请求身份、执行回读、独立恢复义务；开关视觉与状态文案共同区分“希望关闭”和“尚未恢复”。
- **验收**：开启成功与失败分开；关闭确认可取消；关闭失败可重试；成功关闭后两次重启不自动开启；恢复失败后重启只继续恢复，不重新限充。

### BM1-S03 · 可调整的充电上限

- **业务目的**：以一个清楚的目标替代复杂自动模式。
- **使用者**：有内置电池且当前限充通道支持 80–100% 的用户。
- **触发**：上限滑块与“应用/保存”；预留 `si.bm.simple.limit`、`si.bm.simple.apply-limit`。
- **流程**：调整草稿 → 显示尚未应用 → 点击提交 → 请求中 → 回读成功后更新有效值。保护关闭时仅保存，下一次手动开启才执行。
- **规则**：默认 80%，整数 80–100%；100% 是长期上限选择，不引入临时充满模式。超过上限不自动放电。主动放电执行期间不更改长期上限；先停止放电，再调整。
- **边界**：失败保留原有效值及待重试草稿；权限或读数不可用时不提交控制；串行请求和版本检查防止旧请求覆盖新设置。睡眠时不能从界面发起修改。
- **数据**：草稿、已保存上限、已确认设备上限、保护意图、请求序号、最后结果。
- **验收**：80→82→确认生效；模拟/注入失败时仍保留原有效值；关闭时保存90不启动充电控制；当前86/上限80不触发主动放电；两入口保持一致。

### BM1-S04 · 主动放电与随时停止

- **业务目的**：用户明确需要降低电量时执行一次可停止的放电。
- **使用者**：保护已开启、已接电、读数有效且设备实际支持主动放电的用户。
- **触发**：“开始放电”及目标弹窗、“停止放电”；预留 `si.bm.simple.discharge`、`si.bm.simple.discharge-target`、`si.bm.simple.stop-discharge`。
- **流程**：输入目标 → 前置检查 → 确认 → 硬件动作与读数核验 → 显示目标及进度 → 到目标自动停止或用户主动停止 → 恢复长期上限管理。
- **规则**：目标为整数，最低20%，必须低于提交瞬间有效电量；弹窗默认取充电上限与当前电量减1中较低值。长期上限不因主动放电而改变。目标低于上限时，结束后恢复上限管理可能重新充电，开始前必须明确说明。
- **边界**：电量≤20%、未接电、未开启保护、未知读数、未授权、其他控制冲突或能力不足时不可开始，说明原因。提交前重校验电量和目标；进行中读数或供电异常不能继续盲放。重复停止可安全重试，恢复失败不能显示已完成。
- **数据**：一次性操作身份、开始电量、目标、当前读数、停止原因、长期上限、控制所有权和恢复结果；不把放电目标写成长期限充设置。
- **验收**：当前86时目标90被拒绝；目标80到达后停止且上限不变；手动停止可用；上限82/目标80结束后按82管理且提示不误导；不支持设备不接受请求。实际设备必须观察真实电量下降和稳定恢复供电，接口返回成功不足以验收。

### BM1-S05 · 睡眠默认保护与临时放电中断

- **业务目的**：用户不需要额外配置，睡眠仍按充电上限保护。
- **使用者**：保护已开启且设备限充通道能在睡眠期间持续生效的用户。
- **触发**：系统进入睡眠和唤醒；无产品开关、无独立设置分区。
- **流程**：进入睡眠时保持长期上限；若主动放电正在执行则结束并恢复稳定供电/上限管理；唤醒后重新读取状态并展示真实结果，不自动继续放电。
- **规则**：不建立阻止睡眠的断言，不主动锁屏、不另建唤醒计划。保护关闭时不因睡眠开启；用户设100%时睡眠也遵守100%。睡眠保护必须由可在睡眠中生效的控制能力承担，不能靠 UI 定时轮询假定持续运行。
- **边界**：收到睡眠通知不等于恢复成功，不能无限延迟或拦截睡眠；未能确认限充/恢复时保留故障与恢复义务，唤醒明确显示并核验。未验证设备不能宣传睡眠期间已受保护；不可静默转成强制保持唤醒。
- **数据**：睡眠边沿、长期上限、保护意图、临时操作身份、设备限充回读、唤醒后的采样和恢复结果。
- **验收**：真实睡眠期间上限不被移除或重置为100；正常/合盖睡眠及唤醒分别核验；睡眠中断主动放电后无续跑；保护关闭后睡眠/唤醒不重新开启。仅“睡前保存80、醒来显示80”不足以证明睡眠期间未继续充满。

### BM1-S06 · 权限、失败和恢复反馈

- **业务目的**：错误可理解、可处理，不再出现“看起来开启但没有生效”。
- **使用者**：遇到权限、能力、读数、外部控制或恢复问题的用户。
- **触发**：启动检查、控制请求、重试、重新读取及系统事件；预留 `si.bm.simple.notice`、`si.bm.simple.retry`。
- **流程**：发现问题 → 在当前控制区域显示简短原因 → 提供适用的授权/重试/读取入口 → 核验结果后更新，不新增复杂诊断页。
- **规则**：恢复优先于新控制；失败不循环重试硬件写入。不会为解决冲突自动退出其他 App 或改其设置。未完成恢复的安全义务保留，即使用户保护意图已经关闭。
- **边界**：恢复操作与开始新控制分开；不能因为读数未知而删除已有恢复入口。辅助程序失联、退出、崩溃、晚到响应均不能重新放电或误标成功；原有自有变更恢复底线保留。
- **数据**：失败类别、面向用户的原因、可重试动作、请求代次、控制所有权、恢复记录；诊断不包含私人正文或账户信息。
- **验收**：开始失败、上限应用失败、停止失败、关闭恢复失败分别可重现且不假成功；连续点击/晚到回调/重启不覆盖新意图；错误提示可读且不出现底层协议细节。

### BM1-S07 · 旧高级功能退出与配置迁移

- **业务目的**：精简后后台确实变简单，避免旧规则继续干预充电。
- **使用者**：从完整电池管理版本升级的用户及新用户。
- **触发**：精简版首次启动、旧控制请求到达、升级过程中恢复旧会话。
- **流程**：先阻止旧调度及新高级请求 → 读取现有会话/所有权/恢复记录并备份旧配置 → 停止旧临时模式，恢复自身变更 → 校验恢复 → 仅迁移有效上限与保护意图 → 建立精简版状态。迁移可重入，失败仍保留恢复信息。
- **规则**：新安装默认关闭、上限80。已有有效80–100上限保留；用户明确关闭保持关闭，不受旧自动启用规则影响。旧校准/航海/定时/充满/暂停/断供/能源/灯色/睡眠断言不自动续跑；外部调用旧捷径时返回已移除，不偷偷执行。
- **边界**：旧上限低于80或来源不明时保留原记录，不静默提高硬件限值；停在未启用/需重新选择上限状态，由用户在普通上限区域选择后手动开启。恢复未知时不得丢恢复记录、直接卸载仍负有恢复义务的辅助程序，或改写其他工具设置。
- **数据**：迁移版本、旧配置可恢复备份、旧任务及历史只读记录、控制所有权、未完成恢复、有效上限与明确关闭意图。新控制逻辑只读取精简配置，不将旧归档作为运行配置。
- **验收**：分别从定时、校准、航海、手动暂停、退出保持状态升级；旧任务不执行、旧外部入口不可触发硬件；失败/重启可继续恢复；旧低上限无静默升高；历史及备份可读且不会重新成为活动任务。

### BM1-S08 · 退出、重启与回退

- **业务目的**：简化功能后仍能安全退出和回退，不遗留意外放电或充电限制。
- **使用者**：正常退出、崩溃恢复、升级或回退的用户。
- **触发**：正常退出、辅助程序检测失联、设备重启、安装回退。
- **流程**：退出时停止临时放电并恢复自有控制；记录恢复结果/未完成义务。再次启动先核验恢复，再依据持久保护意图决定是否开始限充；用户关闭则只恢复，不重新控制。
- **规则**：不保留旧“退出继续停充”用户功能，不自动继续放电；正常退出要求明确恢复路径，失联恢复使用现有安全机制。回退应用不等于允许重启旧高级自动化。
- **边界**：未确认恢复时不能宣称“已恢复系统”；保留恢复所需辅助程序和信息。回退说明须区分程序回退与旧配置恢复，不能默认恢复所有高级任务。
- **数据**：保护意图、长期上限、退出/失联原因、未完成恢复、迁移备份定位；历史包与需求快照保留。
- **验收**：放电时退出、限充时退出、恢复失败后崩溃、用户关闭后重启分别测试；无意外持续断供；旧包和备份可回退，默认不会恢复旧任务执行。

## 6. 对抗性验收与交付门槛

| 层次 | 必须验证 | 不足以证明通过的证据 |
| --- | --- | --- |
| 需求与布局 | HTML/PRD/原生页面一致，三个常用操作、双入口同状态、无旧高级入口 | 仅截图、仅文件存在 |
| 状态与竞态 | 上限草稿/有效值、关闭持久化、在途请求取消、失败重试、停止和恢复、迁移重入 | 编译通过或“调用成功”日志 |
| 实际限充 | 目标以下正常充电、到上限停止继续充电、超上限不自动主动放电、解除后恢复系统 | 仅回读已保存的数字 |
| 主动放电 | 真实下降、停止、达标、拔电、未知读数处理、稳定恢复供电 | 仅模式显示“放电中” |
| 睡眠 | 睡眠期间限充持续，唤醒核对，主动放电中断，无额外保持唤醒 | 仅睡前/醒后设置值一样 |
| 迁移与回退 | 旧任务/捷径不可写，旧模式不续跑，自有变更恢复、其他工具状态不被覆盖 | 仅隐藏旧按钮 |
| 既有模块 | 音乐、通知、音量亮度、挂绳、窗口增强和保持唤醒行为无非预期改变 | 只测试电池页 |

控制请求须有有限等待和明确失败结果，具体时序在实现中依据现有控制链路确定并留证，不能把原型550毫秒延迟当作设备承诺。真实充放电、系统授权、睡眠和后台辅助程序变更需按具体测试范围取得授权；本轮 PRD 授权不包含这些操作。

主设备的主动放电与睡眠限充未通过时，整体状态保持“未完成设备验收”，不得以“不支持”提示代替核心功能的完成。确实不具备能力的其他设备需准确说明限制，不能硬开不安全通道。
