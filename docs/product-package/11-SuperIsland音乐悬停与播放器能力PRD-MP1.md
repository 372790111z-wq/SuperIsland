## 2. 目标、范围与证据边界

用户播放音乐时可以先查看一条轻量横条，直接完成常用操作；需要更多内容时再点击进入完整音乐面板。共享一套音乐界面和控制入口，播放器差异封装在能力适配中。

本轮包括：音乐播放时悬停半展开；封面、上下曲、播放/暂停、进度；QQ 音乐收藏与顺序播放/单曲循环/随机播放；能力缺失、状态未知和失败反馈。完整音乐面板与横条复用同一状态和操作。

本轮不增加新的播放器选择设置、全局快捷键或常驻小窗，不改变其他模块正常展开、通知优先级、窗口拖动抑制、Zilan 抑制或系统交互门禁。不重写媒体采集，不接入其他播放器的收藏/模式，不修改 QQ 客户端文件或读取账号凭据，不自动切换用户播放来源。

已确认事实：当前代码已有基础媒体控制；QQ 音乐 11.10.5 的播放控制栏可读“添加到我喜欢”和“播放模式（顺序播放）”，菜单具有三种具名模式。已观察到入口不代表写操作可靠，也不代表所有版本、后台或关闭窗口时可用。已收藏反向标签、实际设置与回读仍需实现阶段验证。HTML 的曲目、收藏和请求结果均为演示数据。

## 3. 已确认交互与状态表

| 状态或动作 | 行为 |
| --- | --- |
| 收起，音乐启用、正在播放、有有效当前曲目，现有优先级允许展示音乐 | 悬停达到现有设置延迟后显示音乐横条，切到当前音乐模块 |
| 鼠标停留在横条 | 保持横条，不因第二次悬停计时自动全展开 |
| 点击歌曲信息或横条空白处 | 进入当前歌曲的完整音乐面板 |
| 直接点击收起的灵动岛 | 保留现有直接全展开入口 |
| 点击封面 | 按现有来源打开逻辑打开播放器/准确来源；不冒泡为全展开 |
| 点击上一首、播放/暂停、下一首，拖动进度 | 只执行对应媒体操作，保持当前面板 |
| 条内暂停 | 不立即跳态；鼠标移开按现有收起延迟收起 |
| 已暂停后重新悬停、没有有效音乐信息、音乐模块关闭 | 沿用现有展开路径，不新增空音乐横条 |
| QQ 音乐 | 在同一横条加入收藏和播放模式；六枚按钮为封面、收藏、模式、上一首、播放/暂停、下一首 |
| 播放模式按钮 | 依次请求顺序播放 → 单曲循环 → 随机播放 → 顺序播放；显示当前模式和下一目标提示 |
| 其他来源 | 共用基础界面；没有实现并验证的高级能力不显示 |
| 能力已识别但状态暂不可读 | 对应按钮显示未知并禁用，不能把未知画成未收藏/默认顺序 |
| 高级操作进行中 | 显示等待状态，禁用重复提交；其他基础操作仍可用，切歌会使旧请求失效 |
| 操作失败或结果无法确认 | 不显示成功；解释失败或待确认状态，重新读取当前状态后允许重试或打开播放器处理 |

悬停与收起延迟沿用用户现有设置，不写死为演示的 0.3 秒/1 秒。横条复用黑色灵动岛、封面、歌曲信息与进度结构；QQ 专属控制在信息区增加一行。HTML 的 408px 宽及内容高度为视觉参考，原生仍遵循已有刘海、安全区、字体和屏幕适配。

## 4. 功能点

### MP1-F01 · 音乐悬停半展开与点击全展开

- **业务目的**：减少查看音乐时无意打开大面板，同时保留进一步操作入口。
- **使用者**：启用音乐模块、存在有效当前播放的本机用户。
- **触发**：收起态鼠标进入灵动岛并达到现有悬停延迟；拟用原生标识 `now-playing-hover-preview`。
- **流程**：检查已有交互抑制与优先级 → 在执行延迟回调时复核播放条件 → 显示当前音乐横条 → 点击信息/空白处全展开，或移开后收起。
- **规则**：只改符合音乐条件的分支；现有通知、扩展和拖动优先级不被音乐抢占。横条内停留不升级；已有完整面板不因播放状态变化自动缩回。点击进入音乐面板时保留来源、曲目和进度上下文。
- **边界**：延迟期间暂停、切源、模块关闭、移出或抑制生效时取消过期展示；条内暂停不强制跳态，离开后重新进入以最新状态判定。现有已打开通知等非音乐内容不被替换。
- **数据**：当前岛状态、音乐模块启用、有效播放快照、当前展示模块、输入/悬停代次及现有延迟设置；不新增持久化开关。
- **验收**：正在播放悬停只到横条，持续停留不全展开；点击信息后全展开；暂停/无信息/模块关闭回退正确；重复进出及边界回调不产生迟到展开；通知、拖窗、Zilan 与系统表情等既有门禁回归。

### MP1-F02 · 共用基础媒体控制

- **业务目的**：在横条内完成上下曲、播放/暂停及进度操作。
- **使用者**：当前播放器提供对应基础能力的用户。
- **触发**：横条或完整音乐面板中的独立控件；拟用 `now-playing-transport`、`now-playing-seek`。
- **流程**：绑定当前播放来源及曲目 → 检查操作能力与当前身份 → 调用现有共用控制入口及来源分支 → 获取后续实际播放状态更新显示。
- **规则**：按钮和进度手势不冒泡为打开完整面板；上下曲按明确方向执行。保留已有系统媒体命令、Spotify/Apple Music 与浏览器处理，不为不同播放器复制横条视图；“有入口”不等于所有播放器支持所有命令。
- **边界**：来源消失、能力不支持或无法确认来源时不能盲目控制另一个播放器；无有效时长时禁用进度操作。连续点击不得产生失控重试；切歌后清除上一首的进度和高级状态，等待新曲目的真实更新。
- **数据**：来源身份、曲目快照、播放状态、时长、进度、基础能力及操作结果；与现有管理器共享，不引入平行状态真源。
- **验收**：横条中每个控件可操作且保持横条；完整面板状态一致；QQ 及现有其他来源分别记录实际支持情况；验证切歌、不可定位进度、播放器退出和来源切换，不用本地图标变化替代实际媒体效果。

### MP1-F03 · 封面打开准确播放来源

- **业务目的**：需要播放器专属操作时能从封面直接返回正确来源。
- **使用者**：已有可识别播放来源的用户。
- **触发**：点击横条或完整面板封面；复用已存在的 `now-playing-open-source` 原生可访问标识。
- **流程**：沿用 NowPlayingSourceButton/NowPlayingSourceOpener → 核验当前快照 → 打开对应应用或已有精确浏览器来源 → 按现有逻辑结束展示。
- **规则**：封面是独立按钮，不触发父容器全展开；保留原有打开中、不可用与失败提示，不拓展浏览器账号或页面访问范围。
- **边界**：来源未知、对应应用不可用或曲目已变化时不打开猜测目标；失败后可重试。HTML 仅演示反馈，不模拟真实打开后的系统窗口切换。
- **数据**：复用来源快照、打开中状态与失败快照，不新增来源配置。
- **验收**：封面能打开当前准确来源；打开过程不触发全展开、不重复发起；切源、未知来源与失败行为符合原逻辑。

### MP1-F04 · QQ 当前歌曲收藏与取消收藏

- **业务目的**：无需离开横条即可管理当前 QQ 歌曲的喜欢状态。
- **使用者**：当前来源为 QQ，已能读取当前曲目及收藏状态且操作可用的用户。
- **触发**：点击心形按钮；拟用 `now-playing-favorite`。未实现能力时隐藏；已识别但状态未知时禁用并解释。
- **流程**：读取当前曲目收藏状态 → 点击时保存目标状态 → 重新核验 QQ 进程、播放控制栏与同一曲目 → 执行一次 → 读取同一曲目新状态 → 仅确认匹配目标后更新成功状态。
- **规则**：已收藏/未收藏/未知三态分开；未知不能默认未收藏。当前候选是精确定位 QQ 主窗口的播放控制栏；不得从推荐页、歌单列表或全局文字搜索中选择“收藏”。半展开与完整面板共享状态，收藏按曲目而非全局单个布尔值保存。
- **边界**：登录、网络、权限、窗口缺失、控件歧义或未验证客户端版本造成不确定时停止动作。已收藏反向标签必须实测，不猜测。重复点击只保留一个在途请求；切歌/切源/退出使旧结果失效。无法避免的读取与动作间竞态需前后复核，不能承诺跨进程原子性。
- **数据**：来源进程身份、曲目标识/可核验快照、请求代次、可用性、已确认收藏状态、目标状态、在途请求及回读结果；不读取账号密钥或用户歌单历史。
- **验收**：同一歌曲收藏与取消均有真实 QQ 状态变化及回读；切歌不会串用状态，返回曲目会重新核验；未知、已登录/未登录、网络失败、窗口关闭、快速重复及换源分别验证。无法确认成功时不点亮心形为成功状态。

### MP1-F05 · QQ 播放模式

- **业务目的**：在横条内查看并选择 QQ 播放模式。
- **使用者**：当前来源为 QQ 且能读取模式、执行目标模式选择的用户。
- **触发**：点击模式按钮；拟用 `now-playing-playback-mode`。图标、可访问名称和提示均反映当前模式。
- **流程**：读取当前模式 → 按第 3 节顺序确定下一目标 → 核验当前来源/会话 → 通过已核验的具名目标执行一次 → 读回一致后更新显示。
- **规则**：支持集合以实测 QQ 菜单的顺序播放、单曲循环、随机播放为基线。顺序由本产品定义，不能假定 QQ 按钮内部切换顺序相同；底层应按具名目标选择。单曲带“1”，随机使用随机图标，顺序有明确模式名称，不能统称“循环”。
- **边界**：未知模式禁用；缺少目标选项或出现新模式不映射成默认值。模式属于来源播放会话，不能按歌曲重置；切源不把旧模式覆盖到新来源。在途发生切歌时丢弃旧回调并重新读取，不能靠回调猜测是否已执行。
- **数据**：可支持模式集合、已确认当前模式、目标模式、来源/会话身份、请求代次及回读状态。
- **验收**：分别验证三个具名目标及相应真实读回；重复点击、切歌、切源和模式不可读时无盲切换；横条与完整面板显示一致；操作不会改变其他播放器模式。

### MP1-F06 · 按能力展示、失败与并发恢复

- **业务目的**：共享界面同时准确表达各播放器的支持范围，避免误操作和虚假成功。
- **使用者**：QQ 及其他基础媒体来源用户。
- **触发**：来源/歌曲变化、面板显示、权限变化、请求执行或回读完成；拟用 `now-playing-control-status`。
- **流程**：取得来源能力快照 → 展示可用控件 → 状态未知时禁用 → 执行中等待 → 成功以回读确认；失败解释原因，重新读取后允许重试或通过封面打开来源处理。
- **规则**：区分未实现/不支持、暂不可用、可用、执行中、失败和结果待确认。不支持的高级按钮隐藏，暂不可用可见但禁用。未证实发送成功不等于没有副作用；超时后标记无法确认并先重读，禁止自动重发 toggle。已确认失败可保留上次已知值并标明失败，不能把旧值称为当前真值。
- **边界**：异常结束、客户端升级、旧进程重启或失去权限使能力失效；不按坐标盲点，不扫描无关列表或全桌面。请求/读取有界且不阻塞主线程，不另开持续高频后台扫描；复用现有模块可见性与刷新生命周期。原型工具栏只用于模拟，不搬进原生产品。
- **数据**：统一能力快照及状态枚举；每个来源由适配器提供数据和操作，视图不写 QQ 特例控制流程。首轮只有 QQ 高级能力；其他播放器高级接入须单独验证。运行日志只留必要状态码，不保存歌曲/歌单历史、账号或原始界面树。
- **验收**：其他来源不出现 QQ 专属按钮；未知不显示假状态；失败可理解、可恢复；换源/切歌后的迟到回调不污染新状态；慢读写下岛仍可交互。模块关闭和 App 退出清理在途工作，原生通知、调度中心及其他功能无回归。

## 5. 数据与实施约束

统一接口的最低语义契约如下，名称为设计语义，不要求原样新增类或替换现有架构：

| 数据 | 语义 |
| --- | --- |
| 来源身份 | bundle ID、运行进程/会话身份；不能仅用显示名选择进程 |
| 曲目身份 | 来源可提供的稳定 ID，或经过验证的当前曲目快照与代次；同名歧义时停止高级操作 |
| 能力 | 播放、切歌、seek、打开来源、收藏读/写、模式读/写及暂不可用原因；分别判断 |
| 收藏 | 已收藏、未收藏、未知；包含所属曲目和读取时间 |
| 模式 | 顺序、单曲循环、随机或未知；包含来源/会话与读取时间 |
| 请求 | 来源/曲目代次、目标值、在途状态、有限等待、已确认/失败/无法确认结果 |

候选复用文件：`AppState.swift`、`IslandContainerView.swift`、`NowPlayingExpandedView.swift`、`NowPlayingManager.swift`、`NowPlayingProvider.swift`、`NowPlayingSourceButton.swift`。实际修改前再核查最新工作树，不在 PRD 阶段改业务代码。

实现必须先证明 QQ 的准确定位、状态读取和单次操作回读路径；读取入口的证据不允许直接升级为“已支持控制”。其他播放器只复用已存在基础控制，不在本轮擅自加入账号 API、逆向私有网络写入或新的权限申请流程。
